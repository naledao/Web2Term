# DeepSeek 隐藏原网页诊断（用户运行）

用于区分专注视图卡住时的真实视口、页面可见性、动画帧及虚拟列表挂载问题。智能体只写脚本、读取日志，不启动探针。

## 当前优先：采集主应用里的新消息现场

独立探针此前加载已有会话就能读到历史消息，升级运行时后的主应用新消息仍会卡住。因此本轮需要记录真正卡住的那个视图，不再靠另开页面推断主应用状态。

先结束当前开发进程，在项目根目录 PowerShell 运行：

```powershell
$env:WEB2TERM_HIDDEN_VIEW_DIAG = '1'
npm run dev
```

1. 新建一个 DeepSeek 会话，保持“专注对话”，发送一次“当前机器配置”。
2. 如果仍卡住，保持该视图约 **15 秒**，不要重复发送。
3. 切到“原始”，等 **5 秒**；再切回“专注对话”，等 **5 秒**。
4. 告诉智能体“应用内日志好了”。日志同步追加，无需关闭软件才能读取。

本模式由用户启动主应用；探针模块只观察应用已经创建的 WebContentsView，不创建窗口、启动 Electron、加载额外网页、改尺寸/可见性、改代理/资料目录、重发消息或执行命令。主应用自身的发送及命令执行规则保持原样。它仅在未打包的开发模式、该环境变量精确为 `1`、DeepSeek 平台下加载；发布版不会加载 `tools/diag` 文件。

日志路径为 `%TEMP%\gpt-login-diag\deepseek-hidden-app-<UTC 时间>-<进程号>.log`。`APP-ATTACHED` 记录实际 Electron/Chrome 版本及 `viewId`，用于与 `deepseek-reply` 日志对照。`APP-SAMPLE` 同时记录应用请求尺寸、原生实际尺寸、窗口裁剪尺寸、缩放、可见性、网页视口及观察器计数。按 `viewId` 区分多个会话，按 `documentSequence` 区分完整页面加载；不记录会话编号或完整 URL。

页面采样每秒最多一次，仅在专注视图请求数据以及之后 15 秒内写日志；导航后丢弃旧文档采样，未返回的读取不会不断堆积。主进程按固定字段白名单脱敏，额外记录顶层及滚动/虚拟列表容器的尺寸，不读取或记录它们的正文。探针读取布局和注册观察器可能改变页面时序，不能把“开启探针后不卡”直接视为已修复。

`APP-SAMPLE.phase=baseline` 时不读 DOM 布局、不请求动画帧、不注册页面观察器；当应用的快照连续等待且没有回复超过约 10 秒，才切换为 `layout-observers`。对比阶段切换前后的行数，可以检查附加测量是否让页面恢复，避免把探针影响当作正常行为。

本轮结束后，在该 PowerShell 中取消诊断开关，再正常启动应用：

```powershell
Remove-Item Env:WEB2TERM_HIDDEN_VIEW_DIAG -ErrorAction SilentlyContinue
```

## 独立窗口对照（本轮无需重跑）

先关闭正在运行的 Web2Term 和其他诊断窗口，避免同时使用同一个浏览器资料目录。以下命令是用户运行的独立诊断入口；正常项目仍只用 `npm run dev` 启动。

在项目根目录 PowerShell 执行：

```powershell
Set-Location 'C:\codes\gpt-web-to-codex-terminal'
$env:PROBE_START_URL = 'https://chat.deepseek.com/a/chat/s/52d88cb6-adf4-40e6-b4d8-e6a22582cf73'
.\node_modules\electron\dist\electron.exe .\tools\diag\deepseek-hidden-view-probe.cjs
```

1. 窗口会打开，但原网页最初隐藏；先等约 **15 秒**，不要切换。
2. 按 **Ctrl+3**（或顶部“视图试验 → 再次调用保活”），再等 **5 秒**。
3. 按 **Ctrl+1** 显示原网页，等 **10 秒**。观察这条已有会话是否能显示原先的回答，无须重新发送。
4. 按 **Ctrl+2** 隐藏网页，等 **10 秒**，再按 **Ctrl+1**，等 **5 秒**。
5. 关闭窗口。日志自动保留，告诉智能体“探针跑好了”即可；无需截图或复制正文。

如原会话没有回答，可选：在网页显示时手动发送一次简单普通问题，发送后立即按 Ctrl+2 隐藏，等待约 15 秒，再 Ctrl+1 显示。探针不提供机器环境信息或工具协议，不连接终端，不能替代应用的自动执行测试。没有出现问题也要如实保留日志。

如果显示后遇到登录或人机验证，停止本轮并告知；不要反复登录或发送。日志中 `route=other-origin` 不会执行页面采样。

## 日志及边界

终端在开始、结束时打印唯一日志路径：

```text
%TEMP%\gpt-login-diag\deepseek-hidden-view-<UTC 时间>-<进程号>.log
```

- `START`：实际 Electron/Chrome 版本，初始隐藏模式。
- `NATIVE-STATE`：用户操作/尺寸变化及请求尺寸、实际尺寸、原生视图可见性、窗口状态、节流设置和主框架可见性。
- `KEEP-ALIVE`：加载、隐藏及每 5 秒兜底调用的时间。复用当前应用的保活方式，不自动显示/点击网页。
- `SAMPLE.page`：`innerWidth/innerHeight`、视觉视口、文档/正文/输入框的尺寸；定时器、动画帧、ResizeObserver、IntersectionObserver、DOM 变化计数；虚拟行、助手内容、思考、代码块及错误容器数量。
- 观察器每秒最多请求一次动画帧，记录是否一直等待。不是每帧采集 DOM，不会从 1 Hz 帧计数推算真实帧率。
- 原始与隐藏状态的切换由用户操作，日志中的计数不能单独证明服务端已成功回答。
- `PAGE-READ-FAILED` 或 `pagePending=true` 表示读取失败/尚未返回，不能当作“没有消息”。关闭时最多额外等待约 700 毫秒，日志超出 4 MiB 后停止追加。

不记录聊天正文、草稿、用户按键、消息编号、完整 URL、HTML、附件内容、Cookie、storage、认证头、请求/响应正文或截图；主进程再次按固定字段白名单过滤。日志使用 `fs.appendFileSync` 同步追加，只注册一次请求身份处理器，不安装应用提示词注入、工具解析或命令执行模块。

默认复用应用的 `persist:deepseek`。`PROBE_USER_DATA` 可指定其他资料目录；`PROBE_PROXY` 默认为 `http://127.0.0.1:7897`，仅作用于探针会话，`direct` 可切换为直连。探针不读取/修改应用保存的代理设置。`PROBE_START_URL` 只接受无凭据、查询参数和片段的 DeepSeek 同源地址，不会写入日志。

构建通过只说明项目静态构建完成，真实诊断等待用户运行。读取这份日志后，再决定具体修复；本探针不是已经解决卡顿问题的声明。

## 已有结果及升级后的快速复查

2026-10-30 的首份日志记录 Electron 44.4.3：初始隐藏时视口和动画帧正常，但框架报告 `visible`、文档报告 `hidden`；手动保活无效，第一次显示后文档才变为 `visible`，再次隐藏仍保持 `visible`。本轮已有历史行始终存在，没有采集新消息，因此不能宣称复现了主应用整条故障链路。

当前项目已把 Electron 最低版本提高到 44.5.0，以包含文档可见性即时同步的上游修复。生产代码已去掉无效的每 5 秒兜底；本探针保留原来的对照流程和日志格式，便于只改变运行时版本进行比较。

如果只复查该状态，更新依赖后使用上面的相同命令，**初始隐藏等 15 秒后直接关闭窗口即可，不必显示或发消息**。应检查 `START.electron` 确为 44.5.0 或更高，并检查加载后的 `SAMPLE.page.visibility` 能否在原生视图仍隐藏时变为 `visible`。主应用的自动执行功能另由用户通过 `npm run dev` 验证。
