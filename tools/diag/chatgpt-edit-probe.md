# ChatGPT 编辑已发送消息 · 用户操作探针

为「专注会话」实现编辑和重新发送之前，测量 ChatGPT 原网页的真实行为。此轮只采集，
不修改专注会话实现。**用户运行、用户操作，智能体读日志。**

## 运行

先关闭正常应用。探针使用应用的 `persist:chatgpt` 分区，共用登录状态。
在项目根目录的 PowerShell 运行：

```powershell
Set-Location 'C:\codes\gpt-web-to-codex-terminal'
.\node_modules\electron\dist\electron.exe .\tools\diag\chatgpt-edit-probe.cjs
```

默认代理为 `http://127.0.0.1:7897`。需要更改时，只为本次终端设置：

```powershell
$env:PROBE_PROXY = 'http://127.0.0.1:端口'
# 或 $env:PROBE_PROXY = 'direct'
```

`PROBE_START_URL` 可指定 `https://chatgpt.com` 同源会话地址。
`PROBE_USER_DATA`、`PROBE_PARTITION` 可指定独立资料目录、分区；默认无需设置。
探针不读取应用保存的代理配置。

网页加载与网络监听初始化独立进行；网络监听等待超过 5 秒会记录 `NETWORK-UNAVAILABLE`，
不会阻止页面显示。`PAGE-LOAD-START`、`DOM-READY`、`PAGE-LOADED` 分别表示开始导航、
页面 DOM 就绪和页面加载完成。如果窗口仍空白，关闭窗口后把本轮日志路径发给智能体，
不需要反复重启或尝试登录。

## 必做操作（约 3～5 分钟）

建议使用一个专门的纯文字测试对话，避免改动重要历史。编辑会真实重发给模型，
原分支后续回复将从当前视图切走，这是你手动操作原网页的正常结果。

1. 打开一个有 **3 条用户消息及对应回复** 的测试对话，或者手动新建并依次发送：
   - `只回复：第一轮苹果。`
   - `只回复：第二轮香蕉。`
   - `只回复：第三轮橘子。`
   每次等回复完全结束。
2. **按 F5 刷新一次**，等历史消息恢复，再等 3 秒。
   这一步用于取得编辑前的消息分支图。不要只在空白首页刷新。
3. 鼠标移到**第二条用户消息**上，停 2 秒，**按 F6 记录一次快照**。
   点击它旁边的「编辑消息」铅笔按钮。不要编辑最新的第三条：要观察后续回复怎样被替换。
4. 编辑框出现后停 3 秒，将内容改成 `只回复：第二轮草莓。`，停 3 秒，点击**取消**，再等 3 秒。
   这一步采集编辑框、取消按钮及取消后的历史状态。
5. 再次编辑同一条第二轮消息，改成 `只回复：第二轮葡萄。`。
   停 3 秒，在编辑框内**按 Enter 一次**，等新回复完全结束，再等 5 秒。
   如果 Enter 只换行或没有发送，不要连续按；停 3 秒后手动点「发送」，日志会区分两种行为。
6. **再按 F5 刷新一次**，等消息恢复，再等 5 秒。
   这一步取得编辑后的分支图，并确认重新进入页面时显示哪条回复。
7. 直接关闭探针窗口。终端会打印完整日志路径，把这个路径发给智能体即可。

可以多做一组：再次编辑当前第二条消息，改成 `只回复：第二轮西瓜。`，这次用鼠标点「发送」，
等新回复结束后再刷新一次。这样可以同时比较 Enter 与按钮发送。

如果原网页提供 `1/2` 一类分支切换控件，可手动切回旧分支、停 3 秒，再切回新分支、停 3 秒。
没有这类控件则跳过，探针不会自行寻找或点击。

F6 只读当前页面；F5 是你主动刷新的操作。探针不自动刷新、不自动发送，
也不重放捕获到的请求。不要打开 DevTools，它会占用网络观察所需的 debugger。

## 日志与字段

日志同步追加到系统临时目录，不写进仓库：

```text
%TEMP%\gpt-login-diag\chatgpt-edit-<timestamp>-<pid>.log
```

| 事件 / 字段 | 回答的问题 |
| --- | --- |
| `OBSERVER-READY` / `NETWORK-READY` | DOM 监听、被动网络监听是否成功安装 |
| `SNAPSHOT.turns` / `identityOrder` | 用户回合容器、用户文本单元、消息 ID、页面先后顺序、可见性；编辑后哪些 ID 被替换 |
| `SNAPSHOT.globalEditControls` / `turns[].controls` | 实际编辑按钮及其标签、属性、SVG 标记、可见性和禁用状态 |
| `SNAPSHOT.editors` | 编辑框类型、字数、是否属于历史回合、祖先链、关联按钮、是否命中现有主输入框选择器；用于避免把历史编辑框当成底部输入框 |
| `STRUCTURE` | 用户消息及操作区域的脱敏标签树，不输出原始 HTML；编辑时缺少用户角色标记也会从输入框补采回合 |
| `PAGE-EVENT` / `NATIVE-KEY` | 编辑、取消、发送、Enter/Escape、输入和焦点；操作前快照保留目标所在的原回合 |
| `REQUEST` / `REQUEST-BODY` | 用户操作触发的相关接口、方法、请求 JSON 结构、消息 ID、父消息 ID、会话 ID 的关联摘要；不保存请求原文 |
| `RESPONSE` / `RESPONSE-SUMMARY` | 状态码、流式事件结构、用户和助手消息 ID、当前节点、父子分支图；所有消息内容只记类型、字数 |
| `COVERAGE` | 观察到哪些状态、是否捕获分支图、是否有采集失败；缺失状态不当成已测过 |

所有 ID 使用**本次运行随机盐的 HMAC 摘要**，同一运行中 DOM、请求和响应的相同原始 ID 会得到相同摘要，
可用于关联；不同运行的摘要不可比较。`data-turn-key` 和用户消息 ID 是否相同由日志决定，不能预先假定。
专注会话目前保存的是本地消息 ID，功能实现时还需要通过已有消息记录关联网页 sourceMessageId。

网络只观察 `chatgpt.com` 的会话、消息、分支等相关 `backend-api` / `backend-anon` 请求。
只读取浏览器已经发送的请求和收到的响应；没有额外的 API 请求。
请求最多 160 个、单个正文最多 2 MiB，分支图最多保留 240 个节点，DOM 重点采集最近 12 个回合。
超出限制或 debugger 无法读取时会明确记录，缺失数据不是「接口不存在」的证据。

## 数据边界

- 不记录聊天正文、草稿原文、模型输出、附件名称或内容、Cookie、Token、请求头、storage。
- 文字和输入值只记长度；固定的编辑/发送/取消等界面标签、结构类名及测试标识可原样记录。
- 会话及消息 ID 脱敏；URL 不记录查询参数值，未知路径段替换为摘要；页面标题不写日志。
- 不安装应用的发送拦截器，不调用本地终端，不执行模型命令，不进行任何自动聊天操作。
- 只注册一个 `onBeforeSendHeaders` 身份处理器，限定在 ChatGPT 主机；只为本探针进程设置代理。
- 使用 `fs.appendFileSync`，关窗前采集最终状态；启动时用 `vm.Script` 检查序列化后的页面脚本语法。

此探针只能为实现提供原网页证据。构建通过仍需用户运行采集，之后才能据日志实现并验收功能。
