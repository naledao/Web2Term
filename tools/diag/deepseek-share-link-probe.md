# DeepSeek 分享链接读取测试

验证预期流程：**新建 DeepSeek 会话 → 发送分享链接和用户提示词 → 模型依据分享对话回答**。
不测试“继续对话”或会话分支，不安装应用的命令拦截器。

智能体只编写探针、读取结果；用户运行并操作真实页面。

从仓库根目录运行，先关闭正常应用，避免争用同一个 `persist:deepseek` 分区：

```powershell
.\node_modules\electron\dist\electron.exe .\tools\diag\deepseek-share-link-probe.cjs
```

默认使用用户提供的分享链接和当前应用的登录分区，进程内代理为
`http://127.0.0.1:7897`。不需要复制 Cookie。可通过 `PROBE_PROXY` 更换本次代理，
通过 `PROBE_USER_DATA` 指定另一用户数据目录，通过 `PROBE_SHARE_URL` 更换分享链接。
这些设置不修改系统代理或应用配置。

1. 初始窗口显示分享页。手动从头到尾滚动，顶部、底部各停 3 秒，用于在内存中收集
   可见原文，核对后续回答的摘录。虚拟列表采集不保证历史完整，日志不会假称完整。
2. 菜单 **诊断 → 普通模式测试并复制提示词**。探针打开独立空白窗口，并将该组提示词
   放进剪贴板。确认页面是新会话，手动关闭“智能搜索”，粘贴、停 3 秒、发送一次。
3. 回答彻底结束后按 **F8**。探针只记录标记问题之后的测试回答，最多 12000 字符。
   如果提示 `ANSWER-NOT-CAPTURED`，把本组问题滚回可见位置，再按 F8；不要重新发送。
4. 菜单 **诊断 → 智能搜索测试并复制提示词**。在另一独立空白会话中手动开启“智能搜索”，
   粘贴、停 3 秒、发送一次，回答彻底结束后按 F8。两组“深度思考”保持相同。
5. 自己对照分享页检查 APK 文件名、版本号、未使用 Compose 的原因和两段原文摘录，
   可通过菜单记录人工核对结果。
6. 关闭全部探针窗口，把 `.log` 文件交给智能体读取。

不要点分享页的“继续对话”，也不要把原文粘贴进新会话，否则无法验证“只发链接”能否读取。
每组只发送一次，登录和安全验证由用户处理；探针不会自动登录、点击、填写或发送。

日志与本轮操作说明均在 `%TEMP%\gpt-login-diag\`：

- `deepseek-share-link-<timestamp>-<pid>.log`
- `deepseek-share-link-<timestamp>-<pid>.txt`

| 日志事件 | 用途 |
| --- | --- |
| `SHARE-REFERENCE` | 可见分享原文的字符数与摘要；全文仅留在内存，不写日志 |
| `PAGE` | 新会话/分享页类别、输入框与回答数量、搜索控制的类名和 ARIA 状态 |
| `NETWORK-REQUEST` | 实际请求是否包含测试标记和分享链接、请求中的搜索布尔开关 |
| `NETWORK-RESPONSE` / `NETWORK-FAILED` | 请求状态；不代表模型已经读到分享页 |
| `TEST-ANSWER` | 用户按 F8 后采集的专用测试回答，以及两段摘录与已观察原文的匹配信息 |
| `USER-REFERENCE-CHECK` | 用户明确记录的人工原文核对结果，独立于自动采集 |
| `ANSWER-NOT-CAPTURED` | 未看到明确归属于本组标记问题的回答 |
| `COVERAGE` | 哪两组完成了采集；缺失证据不等于失败，也不自动宣布成功 |

只说“已读取”、接口返回 200 或通用解释听起来正确，都不能单独证明链接可读。
需要检查链接中才有的具体信息与较早/较晚消息的原文摘录。摘录自动匹配只证明它出现过在
本次采集的原文中，不证明角色、时间位置或完整历史全部正确；这些需人工核对。
客户端网络观察也不能直接证明或否定 DeepSeek 服务端是否抓取了链接。

日志采用同步追加 `fs.appendFileSync`；不记录 Cookie、请求头、请求正文、响应正文、
原会话全文或完整会话 ID。只保存专用测试回答（对常见凭据格式做替换）。
每个窗口只挂一个 CDP 观察器，不重复注册 `webRequest` 监听器。关闭前在 webContents
销毁前做一次有时限的最终页面采集；关闭窗口不会自动把未结束的回答记作结果。

本探针不验证分享链接创建时是否只包含截至所选回答的历史，也不验证后续产品弹框交互。
构建通过不代表真实页面测试通过。
