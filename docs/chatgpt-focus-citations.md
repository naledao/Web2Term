# ChatGPT 专注视图：引用来源

用户截图中的 `command-line +2` 是一组来源入口，原始视图可展开 apt-get、journalctl、
logrotate 三条资料。普通 Markdown 只能保留入口的文字或第一个链接，不能展示该来源列表。

专注视图将原生引用入口保留为按钮，点击后在本地弹层显示来源标题和网址；选择来源链接后由
浏览器打开。支持加载中、重试、查看原始来源，以及 Escape/外部点击关闭和焦点恢复。
弹层限制在专注区域内，来源列表可滚动，并继承浅深色主题。普通正文链接保留链接行为。

入口按当前会话、助手消息 ID、组序号及文字/目标地址签名定位。在用户点击前不操作网页，
也不读取 React 私有对象或猜测隐藏网址。已存在的真实链接可以直接显示；完整来源尚未载入时，
主进程先移动指针触发对应原生 HoverCard，必要时只点击一次重新核对的引用入口。
页面临时阻止该入口的默认链接导航。读取结束移除监听器并关闭已识别的来源弹层。

只读取入口通过 ARIA 明确关联的弹层，或本次操作后出现、包含该入口已知链接的唯一新弹层。
来源必须完整覆盖 `+N` 对应数量，并经过 HTTP/HTTPS 地址、长度、数量及凭据检查。
会话、回复签名、生成代次或窗口焦点变化时停止输入，丢弃过期结果。来源加载失败会明确提示，
不把第一条来源伪装成完整的 `+2` 列表。复制回答保留可读的来源标签，去掉操作元数据。

本次依据用户截图和语义属性适配，没有采集该引用入口的新 DOM 或运行真实会话。
不同版本的原生弹层若没有关联属性或真实链接，可能仍需在原始视图查看。
