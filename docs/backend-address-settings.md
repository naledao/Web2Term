# 客户端后端地址与强制覆盖

在 **设置 → 后端服务** 中提供“强制覆盖后端地址”，选项为“是（默认）”和“否（使用自定义地址）”。当前内置默认地址为 `https://web2term.kangnasi.xyz`。

## 生效规则

- 新安装及升级前没有保存此选项的客户端，默认启用。启动时把以前手动配置或清空的后端地址覆盖为当前内置默认地址，并持久保存。
- 启用时，后端地址框与“清空地址”禁用；保存设置时，主进程也会强制采用默认地址。今后默认域名变化，保持启用的客户端会在启动时跟随新默认值。
- 选择“否”后，可编辑或清空后端地址，点击“保存”生效。关闭状态会持久保存，重启和后续升级不覆盖已保存的自定义地址。
- 选项修改后须先保存，再登录后端。点击取消不保存这次修改。
- 地址实际变化时清除旧后端登录凭据，后续需重新登录；地址未变时保留当前登录。旧地址被覆盖后，关闭选项不会自动恢复原地址，需要重新填写。
- 登录、设备与终端连接、更新说明共用生效地址。切换后端会沿用既有设备连接失效处理，并通知更新说明清空旧数据。

此选项作用于桌面客户端。Linux 设备工具的自定义地址仍通过 `web2term set server` 管理；使用自建服务时，应关闭桌面端强制覆盖并使两端地址一致。MCP 的独立配置不受这个选项影响。

## 实现

`src/main/backend-settings.ts` 统一处理 `backendUrl`、布尔偏好 `forceDefaultBackendUrl`（SQLite 中保存为 `true`/`false` 字符串）及旧登录凭据。启动迁移、设置保存均使用现有 `setSettings` 事务，地址和需要清除的凭据一次提交。

`BackendAuthService` 使用相同规则读取有效地址，拒绝强制模式下指向自定义服务器的登录或验证码请求。登录请求完成后再次检查地址与偏好，避免旧请求把覆盖后的地址改回去。

## 用户验收

智能体只做构建和静态检查；用户运行离线回归，均不连接真实后端：

```powershell
node --test tests/backend-settings.test.mjs tests/web2term-device-management.test.mjs tests/release-notes.test.mjs
```

用例覆盖升级时覆盖旧地址、默认会话保留、旧凭据清除、关闭后保存与重启、自定义或空地址、无效参数不部分保存，以及切换偏好时尚未完成的登录不能回写地址。

由用户通过 `npm run dev` 验收：旧客户端启动后查看新地址和默认“是”；切换“否”并保存自定义地址，重启确认保留；切回“是”确认覆盖且旧登录失效；修改后取消应保留原设置。真实登录、设备连接和更新说明展示仍待用户验收。
