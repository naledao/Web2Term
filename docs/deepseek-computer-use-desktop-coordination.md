# 第 27 项：全局桌面控制协调

本项在 Electron 主进程中增加唯一的 `DesktopCoordinator`，供所有 `SessionRuntime` 共用。同一 Windows 桌面同时由一个自主目标持有租约。目标进入桌面流程后，租约跨模型回合保留，同目标需要的桌面操作和本机命令继续按步骤推进；其他目标的新本机模型命令在准备 shell 之前排队。

computer use 仍是现有工具体系中的新增工具。本项保持原系统提示词正文、助手角色、旧工具 JSON 协议及自动／手动执行规则，不增加逐应用确认、用户选窗或额外规划协议。

## 租约与运行凭据

| 对象 | 归属与用途 | 释放条件 |
| --- | --- | --- |
| 任务级桌面租约 | 绑定 session、platform、conversation、task、generation 与本机 machineId；跨观察、输入、结果交付及等待模型回合保留 | 目标停止／被替换、会话失效／不活动、工具关闭、暂停、等待用户回答、模型普通答复或执行／交付阻塞时让出；已派发动作仍须先退场 |
| 单次运行凭据 | 主进程内部对象身份，绑定真实排队请求及 desktop／command 类型；每次实际执行单独领取 | 调用方在执行器返回后的 finally 释放；本机 shell 提前返回时，还须等待被退役的子进程 close |
| 排队项 | 保存归属、取消信号和实时可执行条件；等待时没有启动本机命令 | 取得凭据、取消、归属失效或应用退出时移除；最多保留 256 项 |

模型不能通过动作参数、历史记录或伪造同名字段取得运行凭据。`ComputerUseTool` 在主进程再次核对当前任务、凭据对象身份和动作类型；释放后的凭据不可重用。会话内仍由既有任务调度器决定下一步骤，全局协调器负责不同任务之间的桌面控制互斥。

普通模型答复只表示当前自动工具回合停止，释放租约不代表业务目标已经完成，沿用原任务的实际结果判断。当前应用仍保留原有“切换驱动会话会中断旧自动流程”的策略；全局协调也覆盖旧执行器迟到返回期间的交接。

## 放行顺序与执行范围

1. 还没有桌面租约时，不同任务的本机命令可以沿用原行为并行运行；同任务的实际操作串行。
2. 第一个符合执行条件的桌面请求，须等待先前已经获准的本机模型命令结束。它成为队列屏障，后到的本机命令不能继续抢占。
3. 取得桌面租约后，只放行同一目标的一个实际操作。同目标的后续命令或桌面动作可以越过其他目标的等待项，避免依赖自己的后续步骤而互相阻塞。
4. 租约让出后，按符合条件的排队顺序接纳其他目标。暂停或手动模式下尚未确认的项不会执行；恢复／点击原有“运行”入口后重新核对条件，不重复创建执行。
5. 无论命令文本看起来是否涉及 GUI，所有新本机模型命令都先经过协调，包括旧入口的无任务关联命令和后台启动器。旧入口由主进程生成临时排队身份，不将历史内容当成自主任务授权。

只读 `read_files`、SSH／Web2Term 远程命令、后台进程的既有监控和就绪通知不领取桌面运行凭据。`wait_for(background_ready/background_finished)` 直接等待原后台监控，不占用单次桌面运行凭据；如果当前目标此前已取得桌面租约，该租约仍按目标生命周期保留。

已经启动的后台程序、用户手动输入的终端命令、其他独立终端以及外部应用仍可改变界面。这些活动不受此进程内租约约束，操作前仍依赖已有的最新观察、窗口完整身份和焦点复核。全局协调不声称锁住 Windows、拦截用户输入或终止外部进程。

## 取消、退场与旧观察

排队期间取消可直接移除请求；不会准备 shell、启动命令或发送桌面输入。任务概况保持 `waiting-tool`，步骤保持 `queued / not_executed`，并显示“等待全局桌面协调放行”。没有通过额外模型请求轮询队列。

已经派发的操作被取消时，取消信号使其后续步骤失去授权，当前凭据仍等执行器返回后释放。`releaseSession` 和应用退出同样不能提前释放执行中的凭据。

Windows helper 在超时或取消后可能先返回未知结果，再退役原生进程。只要 helper 的 PID 尚在且状态没有 ready，全局入口同时阻止新的桌面操作和本机命令；确认进程关闭或后端真正 ready 后才重新调度。不会用“已等待若干毫秒”代替退场事实。本机 shell 的关闭／重置也可能先结算 run，再结束子进程；`whenQuiescent` 将交接推迟到这些退役子进程发出 close。

桌面租约持有者变化时，统一撤销全部主进程输入观察绑定。返回原任务后须重新观察，不能用旧坐标或旧 observation_id 继续输入；已经生成、等待交付的截图仍能按原任务身份准备和回传。交接不删除跨应用历史线索，也不延长这些线索的执行授权。

运行凭据、租约和队列只保存在当前主进程内存中。重启后不从数据库恢复，不重新执行旧排队项；现有持久任务历史继续用于说明中断事实。
