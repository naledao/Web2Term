# Windows 本机远程终端

Windows 设备端直接运行在 Web2Term 客户端主进程中。登录沿用客户端已加密保存的后端凭据，不需要单独下载工具、再次输入邮箱验证码或安装 sshd。通信沿用 `/ws/agent` 和终端协议 v1，PowerShell 由 ConPTY 承载。

## 开启与使用

1. 使用 Windows 10 1809 或更新版本，启动客户端并登录后端。
2. 打开设置中的设备管理，点击“开启本机远程终端”。首次开启生成当前后端、当前账号独立的设备 ID；重启和重连保留这个 ID。
3. 等待状态显示“在线”。只有收到后端的心跳确认后才显示在线。
4. 在另一台运行新版 Web2Term 的电脑登录同一后端和账号，刷新设备列表，选择这台 Windows 电脑并连接。
5. 在终端中输入 PowerShell 命令，或让 AI 使用该终端执行任务。优先使用 PowerShell 7，未安装时使用 Windows 自带的 PowerShell 5.1。

Windows 设备端和连接它的客户端都需要包含本次 PowerShell 协议适配的版本。旧客户端只支持远程 POSIX Shell，无法使用 Windows 设备终端。

此功能默认关闭。开启后，远程终端以运行客户端的 Windows 用户权限执行。客户端隐藏到托盘后保持在线；完全退出客户端、关闭开关、登录过期或更换登录凭据会回收终端。开启状态保存在本地，下次启动客户端并拥有原账号的有效登录时自动连接。

开启记录绑定后端和用户 ID。切换后端或账号不会自动向新账号开放本机，需要关闭后重新开启；回到原后端、原账号可恢复原设备身份。设备 ID 损坏时报告配置错误，不悄悄生成新设备。

本版随客户端启动，不注册 Windows 服务，也不修改 Windows 的登录启动项。机器重启后需要启动客户端；不等同于 Linux 的 systemd 开机自启。

## 终端与连接行为

- 每台设备最多 3 个终端，包含创建中和等待退出确认的终端；关闭中的原进程仍占用名额，避免重连期间超额创建。
- 每个终端有独立的 PowerShell、当前目录、变量和输出。支持终端输入、输出、尺寸调整和独立关闭；原始终端协议保留 ANSI 和 Ctrl+C 等控制字节。
- 客户端的命令执行界面会进入独立的 PowerShell 命令循环，以命令结束标记报告退出码和当前目录，支持中文路径、盘符路径和 UNC 路径。初始化脚本和命令都通过短行 Base64 输入，每段数据 192 字符，连同加载语法保持在 `Console.ReadLine()` 默认的 254 字符限制内；加载时检查初始化数据长度。中断命令通过关闭该终端并重新创建会话完成。
- 命令循环使用 .NET 自带的 `Console.ReadKey(true)` 逐键读取并组装协议帧，不回显输入，也不再通过 `Add-Type` 动态编译 C# / P/Invoke 控制台接口。远端无需为初始化准备 C# 编译器或引用程序集；保留控制台 Ctrl+C 行为和输入长度上限。
- PowerShell 初始化先单独切换输入模式，收到设备确认后再发送命令循环脚本，避免 PSReadLine 提前读走后续输入。连接日志用 `shell_initializing`、`shell_input_ready`、`shell_ready` 标识阶段；失败时记录 `phase` 和已接收的字节数。脚本错误还记录 `bootstrapStage`（解码、控制台接口、输入模式、编码或命令循环）及受限长度的 `errorId`，不记录终端正文或完整异常文本。
- 停用 PSReadLine 后，原生 ConsoleHost 的多行函数和 `try/catch` 块用额外空白行提交；只有结束花括号不会执行输入块。初始化加载器为两个多行块分别发送空白终止行。
- 握手、等待心跳确认和阻塞发送的超时均为 10 秒；每次确认心跳后等待 20 秒再发送下一次心跳。
- 网络异常按 1、2、4、8 秒递增等待，最多 30 秒，并加入最多 20% 的提前随机偏移。重连成功后重置等待时间。断线会关闭旧终端，不恢复其中的进程。
- 登录到期、认证拒绝、设备禁用、协议拒绝、服务端正常关闭（包括同设备实例替换）停止自动重试，设置页显示处理提示。
- 沿用客户端“软件代理”设置，不使用聊天网页的 Cookie 和浏览器会话。握手凭据只在主进程中传递，不发送给渲染进程。

后端本次增加了终端打开请求的跟踪：桌面客户端断开时，向原设备连接发送各会话的 `terminal_close`，包括仍在创建的终端；设备断开或被替换时结束桌面通道，避免客户端仍显示旧终端可用。跟踪绑定实际设备连接，不把旧连接的清理发给替换实例。

**应同步更新后端以获得上述断线清理行为。** 本次只修改仓库中的后端代码，没有部署线上后端。现有后端仍可转发正常终端操作，但没有这项清理保障。

## 打包与诊断

使用 `node-pty@1.1.0` 自带的 Windows Node-API 原生预编译文件；只在收到终端创建请求时加载。整个 `node-pty` 包从 `app.asar` 解包，并从真实磁盘路径加载，保证 ConPTY 的工作线程和进程清理辅助脚本能访问。安装包资源检查会核对关键原生模块和脚本存在。

运行日志位于 `%TEMP%\gpt-login-diag\web2term-windows-agent-*.log`，完整路径显示在设备设置中，也会包含在现有的诊断日志导出中。使用同步追加记录时间、设备 ID、连接阶段、HTTP 状态、关闭码、会话 ID、终端错误码及退出码。日志不记录访问 Token、验证码、命令、输入内容和输出正文。

## 用户验收

智能体只执行构建，不启动 Electron、PowerShell 终端或运行以下测试。交付状态为“构建通过，等待测试”。

由用户运行离线回归：

```powershell
node --test tests/windows-agent.test.mjs tests/web2term-reconnect.test.mjs tests/web2term-environment.test.mjs tests/remote-interrupt.test.mjs tests/ssh-directory.test.mjs tests/project-terminal-notes.test.mjs
```

这些 Node 用例使用合成 WebSocket、PTY 和时钟验证 Windows 设备逻辑，包含并发限制、退出确认、UTF-8 分片、消息大小校验、身份绑定、心跳、重连、登录到期、PowerShell 命令封装和远程环境识别，不启动真实 Shell 或第三方服务。

由用户在 `backend` 目录运行后端回归：

```powershell
go test ./internal/httpapi
```

后端回归使用测试临时数据库和本机回环 WebSocket，不连接真实后端或运行 Shell。

真实会话验收只通过仓库规定的开发入口启动：

```powershell
npm run dev
```

建议使用两台电脑按上面的开启流程验收：

1. 验证默认未开启，开启后设备出现且状态等待心跳确认；设备在线后能从另一客户端连接。
2. 执行 `$PSVersionTable.PSVersion`、`Get-Location`、`Write-Output '中文输出'`，确认环境和目录指向 Windows 设备。进入已有的中文、空格目录，重连后确认目录恢复；执行不存在的路径，确认非零退出码。
3. 同时打开 3 个终端，确认目录互不影响；第 4 个被拒绝。关闭其中一个并等待退出确认后，可以再打开一个。
4. 执行持续输出或长时间等待的命令，使用中断和重置，确认旧进程与终端名额回收。分别在 PowerShell 7 和仅有 5.1 的机器验收。
5. 断开设备网络，确认旧终端关闭、设置页等待重连，网络恢复后设备 ID 不变；原终端由连接端显式重新创建。
6. 更新后端后，强制退出远端客户端或断开其网络，确认设备端相应 PowerShell 被回收；设备端退出时连接端也显示断开。
7. 验证托盘保活、关闭开关、完全退出、重新启动、登录过期及切换后端/账号的行为。出现问题时提供设置页日志路径对应的日志或导出的诊断日志。

构建通过仅说明类型检查和编译完成，不代表 ConPTY、真实后端代理链路或安装包运行行为已经验收。
