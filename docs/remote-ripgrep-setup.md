# 远端 rg 检查与 AI 安装提示

SSH 或设备远程终端每次建立新连接后，软件复用当前执行终端的环境探测，检查 `command -v rg` 和 `rg --version`。只有明确缺少可用的 rg 才显示建议安装弹窗；探测失败或未知状态不当作未安装。

弹窗展示目标机器，提供“暂不安装”和“让 AI 安装”。拒绝只作用于本次实际连接，切换界面、改变目录或 SSH 命令通道重开不重复提示；断开后重新连接会重新检查。对本机终端不显示这个提示。

用户同意后，主进程核对会话、模型、对话与远端连接，构造安装要求，通过现有 AI 用户消息通道发送。软件不直接执行安装命令、不切换执行模式。AI 根据远端实际系统、架构、权限和包管理器处理安装，最后在同一远端终端执行 `command -v rg && rg --version`。安装步骤与结果沿用现有对话和命令记录。

参考 [ripgrep 官方安装说明](https://github.com/BurntSushi/ripgrep#installation)：优先使用已有系统软件源或 Homebrew；用户目录安装需使用官方发布文件、匹配实际架构并核对校验信息，同时让当前及后续远端终端能直接使用 rg。

AI/终端忙碌、终端模式未启用或页面尚未就绪时，保留提示并说明原因，不打断现有任务或自动排队发送。发送结果不明确时停止重发，提示用户先查看原对话。发送成功仅表示任务已交给 AI；后续命令空闲或任务结束时重新探测，只有实际检测可用才更新环境为 rg 已就绪。

## 用户验证

仅由用户通过 `npm run dev` 启动应用。

1. 连接缺少 rg 的远端，确认弹窗中的机器名称和地址正确。选择暂不安装后，当前连接内不重复弹窗，终端仍可使用。
2. 断开并重新连接同一机器，应重新检查。已有可用 rg 的远端不弹窗。
3. 选择让 AI 安装，确认安装要求出现在当前对话、命令在正确远端执行。手动/自动执行继续遵循当前终端设置。
4. 安装后检查对话中的实际版本输出，并检查后续环境提示已识别 rg。失败时查看实际错误，不把发送成功当作安装成功。
5. 分别检查 SSH 与设备远程终端；连接切换或自动重连后，旧弹窗和迟到结果不能作用于新机器。

用户运行的离线回归用例：

```powershell
node --test tests/remote-ripgrep.test.mjs tests/web2term-environment.test.mjs
```

智能体只编写用例和执行构建，不运行测试、真实远端连接或安装。
