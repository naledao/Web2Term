# DeepSeek 选区追问

使用 `npm run dev` 启动软件，在已有 DeepSeek 会话的一条助手回答正文里选中文字。
在“询问 AI”输入框中填写问题，按 Enter 提交；Shift+Enter 换行，输入法选字的回车不提交。

软件从本地 SQLite 的 `conversation_messages` 读取已保存的对话，截取到所选回答，
生成 UTF-8 的 `deepseek-context.md`。它与软件“对话”视图使用同一个
`ConversationStore.listConversationMessages()` 读取接口，会过滤已识别的终端命令记录。
不创建分享链接、不请求 DeepSeek 历史接口、不收集用于分享接口的认证头，也不生成 HTML。
选区只用于定位本地回答，附件正文来自数据库。已有消息的 Markdown、代码块和表格会保留。
导出的范围是本地已经保存的文字，不补齐网页上尚未保存的更早消息。

匹配优先使用软件捕获消息时的 `sourceMessageId`，而不是虚拟列表行号。
旧数据缺少该标识时，要求正文唯一匹配；没有本地数据、所选回答未保存、匹配不唯一或混入其他会话，
都会保留输入问题并提示原因，不读取其他会话，也不退回分享流程。
消息沿用数据库的阅读顺序，排除所选回答之后的本地记录。

右侧栏复用当前 DeepSeek 登录状态，打开空白新聊天并自动上传 Markdown。
等待附件就绪后，再填入选中文字和用户问题，与附件作为同一条消息发送。
附件仅含会话标题及用户/AI 正文；本次选区和问题位于发送消息中。
历史中的指令作为引用资料处理，提示词会明确区分引用资料和本次问题。
不附加软件内部消息编号、终端执行日志、图片二进制、原附件文件或网页样式。
网页能否完整解析附件仍需真实验收；如果无法读取，提示词要求模型明确告知。

可以在右侧继续追问，原会话在中间保留并可同时操作。“侧边聊天”入口放在右侧「＋」菜单中，默认不占用页签栏。
每次点击「＋ → 侧边聊天」都会创建新的空白聊天，关闭并替换旧实例，沿用当前平台的登录状态；不带入旧选区、旧问题或旧 Markdown，也不自动发送消息。可直接在新聊天中输入问题。
提交新的选区提问仍会打开带有本次上下文的独立聊天。聊天内容顶部不再提供额外的关闭按钮；点击页签上的「×」会关闭并释放对应聊天。切换到其他页签或折叠侧栏仍会保留聊天。
打开侧边聊天或新的选区追问时保留当前侧栏宽度，不自动加宽；仍可拖动边缘调整宽度。新的选区追问会展开已折叠的侧栏；折叠会隐藏并保留聊天。
创建新的选区追问时会替换上一个追问；侧边聊天不会新建软件窗口。
追问网页不连接终端执行；切换会话、平台及打开设置等覆盖界面时，会隐藏相应网页。
返回时重新按当前侧栏位置显示；每个会话只操作自己所持有的聊天编号。

侧栏提供“打开 Markdown”“定位文件”“复制提问”。文件保存在软件用户数据目录的
`exports/deepseek/context-<唯一编号>/deepseek-context.md`，不覆盖已有文件，关闭追问后仍保留。
上传使用临时副本，结束后只清理临时副本；超过 20 MiB 时停止导出。
网页拒绝 Markdown 或上传失败时明确提示；用户修改输入框内容后停止自动提交。
发送只点击一次，同时确认新用户消息中的附件和问题文字；结果不确定时不重复发送。
首次发送产生的新会话路由仅在已点击发送后接受；提交前切换会话会取消上传。

运行时日志：`%TEMP%\gpt-login-diag\deepseek-question-<timestamp>-<pid>.log`。
记录阶段、错误分类、消息数量、Markdown 路径及发送结果，不记录正文或用户问题。
附件日志位于同目录的 `deepseek-file-send-<timestamp>-<pid>.log`，记录上传状态和确认布尔值。

离线回归用例由用户运行（智能体不执行）：

```powershell
node --test tests/deepseek-question.test.mjs tests/attachment-send.test.mjs
node --test tests/side-chat-create.test.mjs
```

真实验收：

1. 在软件“对话”中已有记录的 DeepSeek 会话选择最近及较早回答，确认 Markdown 内容与本地记录一致，且截止到所选回答。
2. 检查代码块、表格、中文；确认文件无网页布局和自动添加的分享链接，本次问题只在发送消息中。
3. 确认右侧第一条消息同时出现 `deepseek-context.md` 附件与问题，模型能引用其中的前文回答。
4. 连按 Enter、整理时按 Esc、切换会话，确认不重复发送、不出现迟到页面。
5. 检查本地无记录、未保存回答和匹配不唯一的反馈，确认问题仍保留，未请求分享接口。
6. 检查登录失效、断网、上传失败，以及打开 Markdown、定位文件、复制提问的手动恢复。
7. 在追问开启时折叠/展开、打开设置及切换会话和平台，确认不覆盖界面、不跨会话显示，关闭后恢复原侧栏。
8. 从「＋ → 侧边聊天」打开新的空白聊天并手动发送消息；再次从「＋」新建或关闭页签后重建，确认没有旧消息、选区或 Markdown，侧栏宽度保持不变。

构建通过仅说明静态检查通过，真实流程由用户运行后依据日志确认。
