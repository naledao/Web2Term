# DeepSeek 选区追问

使用 `npm run dev` 启动软件，在已有 DeepSeek 会话的一条助手回答正文里选中文字。
在“询问 AI”输入框中填写问题，按 Enter 提交；Shift+Enter 换行，输入法选字的回车不提交。

软件在后台获取截至所选回答的历史并创建分享链接，用同一份历史生成离线 `deepseek-context.html`，
随后在主窗口右侧栏显示“询问 AI · DeepSeek”。侧栏复用当前 DeepSeek 登录状态，
在空白新聊天里自动上传 HTML，等待附件就绪，再将选中文字和用户问题与附件作为同一条消息发送。
发送提示词不再包含分享网址。来源链接只保留在 HTML 元信息和“复制来源链接”入口。
可以在右侧继续追问，原会话在中间保留并可同时操作。顶部可切换“侧栏”和“询问 AI”。
打开新追问时自动展开并加宽侧栏，也可拖动边缘调整宽度；折叠或切回“侧栏”会隐藏并保留聊天。
点击“关闭追问”释放该网页视图并回到原侧栏内容。不会新建软件窗口，也不会锁定主窗口。
追问页面只有普通聊天能力，没有终端指令执行。切换会话、平台及打开设置等覆盖界面时会隐藏相应网页，
返回时重新按当前侧栏位置显示；每个会话只操作自己所持有的聊天编号，避免过期布局消息影响其他会话。
分享内容从消息父链确定，不把虚拟列表行号当作真实消息编号，也不包含所选回答之后的消息。

输入框保留失败时的原问题，显示具体原因及日志路径，可按 Enter 重试。
网页原生的“创建分享链接”弹窗不会被打开，系统剪贴板不会在后台创建链接时被改写。
侧栏提供“打开 HTML”“定位文件”“复制来源链接”“复制提问”入口。
HTML 保存在软件用户数据目录的 `exports/deepseek/<分享编号>-<唯一编号>/deepseek-context.html`，
不覆盖已有文件；关闭追问后仍保留。上传使用临时副本，结束后只清理临时副本。
文件为 UTF-8 静态文档，包含按时间排序的用户/助手文字及本次选区和问题，保留原始 Markdown 标记，
不执行历史中的 HTML 或脚本，不加载站点资源，也不包含认证信息、推理过程、图片或原附件文件。
历史中的指令作为引用资料处理，当前发送提示词会明确区分引用资料和本次问题。
HTML 超过 20 MiB 时停止；上传入口不接受 HTML 时明确提示，不会自动改发网址或单独发送问题。
自动发送只点击一次；同时检查新用户消息里的附件和问题文字，不能只凭输入框清空显示成功。
首次发送产生的新会话路由只在提交后被接受；提交前切换会话会取消，未确认时不重复自动提交。
网页能否解析 HTML 附件仍需真实验收；如果无法读取，发送提示词要求模型明确告知。

此前探针只观察到页面增量历史响应中的空 `chat_messages`。
正式实现单独 GET `/api/v0/chat/history_messages?chat_session_id=...`，不携带页面缓存提示或条件请求头，
再校验会话编号、所选回答正文及完整父链。空列表、未知结构、重复回答和不完整历史都会停止，
不使用固定消息编号或自动退回分享弹窗。这个完整读取路径仍需用户在真实会话中验收。

运行时日志：`%TEMP%\gpt-login-diag\deepseek-question-<timestamp>-<pid>.log`。
包含阶段、错误分类、消息数量、最终分享链接、本地 HTML 路径及附件发送结果，不包含认证头、正文或用户问题。
附件诊断日志位于同目录的 `deepseek-file-send-<timestamp>-<pid>.log`，仅记录上传状态和确认布尔值。
复用现有的单个 `onBeforeSendHeaders` 监听器，不占用上传流程所需的 debugger。

离线回归用例已编写，由用户运行（智能体不执行）：

```powershell
node --test tests/deepseek-question.test.mjs tests/attachment-send.test.mjs
```

真实验收：

1. 分别选择最近和较早的一条回答，确认右侧栏的问题、引用文字，以及 HTML 只包含截至所选回答的父链历史。
2. 连按 Enter、在创建链接时按 Esc、切换会话，确认不会重复发送或出现迟到的追问页面。
3. 新聊天里继续追问，折叠、展开或切换侧栏内容，确认聊天保留、原会话可操作，终端任务不接收子聊天内容。
4. 检查登录失效、断网及空历史时的错误反馈；输入问题不丢失。
5. 检查明暗主题、窗口及侧栏缩放、打开/定位 HTML、复制链接/提问，以及自动发送未确认时的手动恢复。
6. 在追问开启时打开设置、切换会话和平台，确认网页不覆盖界面、不跨会话显示；关闭追问恢复原侧栏。
7. 确认右侧新聊天第一条消息同时出现 `deepseek-context.html` 附件和问题文字，提示词没有旧分享网址，
   模型回答引用 HTML 中真实的前文；只收到文件、只收到问题或文件解析失败都不算上下文传递成功。

构建通过仅说明静态检查通过，真实流程由用户运行后依据日志确认。
