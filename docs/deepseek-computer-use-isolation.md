# 第 41 项：会话、平台与控制面隔离

交付状态：**构建通过，等待测试**。智能体只完成代码、离线用例、语法检查及构建，未运行测试，未启动 Electron／helper，未操作真实桌面或访问真实 DeepSeek 会话。

## 实现效果

AI 在浏览器、编辑器、表格和文件管理器等业务窗口间工作时，仍属于用户最初布置的同一任务。任务的会话、平台、对话、代次、执行机器和结果目的地不会因前台窗口变化而改变。

用户主动切换 Web2Term 的驱动会话或模型，控制页面更换对话、重载或被关闭时，软件撤销原任务后续执行权并保留其历史。回到旧会话不会自动继续；继续原目标需沿用第 32／38 项的显式恢复，建立新任务代次并重新观察。

computer use 任务运行时，模型选择按钮允许用户切换，提示“切换模型将中断当前 computer use 任务”。主进程在切换前中断旧任务；非 computer use 关联的运行中任务，以及尚在提交的人类消息，继续沿用原有切换保护。无需新增确认弹窗。

现有系统提示词正文、助手角色、工具调用格式和确认规则保持原样。本项只增加控制归属校验和 computer use 的业务窗口范围说明。

## 控制归属与业务窗口分离

| 情况 | 行为 |
| --- | --- |
| AI 调用 `focus_window` 或在不同业务应用间切换 | 继续使用原任务归属；观察绑定按原规则更新，不把前台窗口当成控制会话。 |
| 用户切换 Web2Term 驱动会话 | 中断原 computer use 任务，作废待执行／待发送内容和旧输入绑定；返回时不恢复执行权。 |
| 用户切换模型平台 | 对任务关联流程先中断旧平台，再选中目标平台；后台旧平台的迟到消息不能成为新平台的任务。 |
| DeepSeek 控制对话改变 | 在切换任务上下文前中断原目标并撤销其页面任务代次，随后只读取新对话历史。 |
| 首次发送后 SPA 分配 conversation ID | 沿用原有补绑例外，保存同一目标和代次，不当作用户切换对话。 |
| 主文档替换／重载，同一对话路径不变 | 页面代次变化仍撤销旧执行权；相同路径不能证明还是原来的控制页面。 |
| 会话关闭／运行实例销毁 | 原有 dispose 流程撤销任务、执行器和工具；销毁后的页面状态、发送确认和文档回调不再访问已清理的页面槽位。 |
| 原执行器迟到回执 | 沿原 UUID 和任务归属更新执行历史，不向新控制页补发，也不恢复旧令牌。 |

任务及动作日志继续使用完整的 `sessionId / platformId / conversationId / taskId / generation` 和机器身份。模型请求不能提供或覆盖这些归属字段；业务窗口的标题、PID、窗口句柄和桌面焦点也不能替代它们。

## 统一控制中断

`SessionRuntime.interruptTaskControl` 用于驱动会话、模型、对话与文档切换。它调用原任务停止链路，并清理当前平台所属的暂存请求、命令候选、回复候选、恢复候选和旧工具结果发送；使原观察输入绑定失效，并重新协调桌面租约及终端／文件任务。

中断已关联目标时，同步调用旧 embed 的 `completeTask` 撤销其提示词／任务代次，结束页面侧任务标记。这里不排队一个可能迟到的新“停止脚本”，避免它影响随后的人类新目标。软件撤销自动流程，不声称网页生成、已发生操作或独立后台进程已经回滚。

原任务关联的后台通知取消回传，后台进程仍按自身生命周期运行。清理按原平台和对话执行；旧隐藏平台文档变化时，不会清空当前平台的待执行内容或取消当前平台的发送。

停止后 `taskEnded` 保持，只有当前活跃控制页确认的人类新目标或显式恢复才能按原规则建立新的执行权。隐藏、已切换或关闭页面迟到的 `onUserStarted` 不清除这一状态，也不创建新任务代次。仍存活的原页面可保留原历史记录；关闭后的回调直接忽略。

## 文字、截图与 IPC 回传

桌面结果发送前复核任务、当前运行实例、可见平台、真实对话和终止状态。文字发送入口增加调用方提供的实时归属校验，桌面、终端／文件结果和任务关联的后台通知均使用相应归属检查。

`ChatGptEmbed.sendTaskResult` 捕获当前提示词代次和页面代次，发送前校验网站 origin 与实际对话路径；收到回执时再核对页面与任务是否仍有效。页面路径相同但 origin 不同，或者原页面已重载、任务被替换，都不能继续原结果的自动推进。

截图沿用第 13 项的单图与文字同消息发送；本项在既有上传期间的归属谓词中增加页面代次，防止同一路径重载后的新文档继续使用旧截图发送操作。旧请求的实际发送或执行事实按既有第 31 项日志语义保存，不能拿来更新新任务完成状态。

`runtimeForEvent` 和 `isManagerEvent` 同时校验发送者是 manager 的真实 WebContents，且发送 frame 正是其主 frame。第三方嵌入页面、其他 WebContents 和子 frame 不获得控制面 API。现有外部模型页面仍没有 preload 桥，模型 JSON 继续经过独立解析及任务校验。

## 原生控制窗口保护

新增 `ControlPlaneWindowPolicy` 和 `ControlPlaneWindowDiscovery`，作为 helper 内所有窗口消费者共享的原生发现入口。

保护依据是实际进程和可执行文件身份：

- helper 启动时捕获当前父进程 PID、helper PID，以及二者实际可执行文件路径。路径不可取得时不启动可用 helper。
- 排除父进程和 helper 的窗口；排除使用相同程序路径的渲染进程、其他窗口与其他实例，不靠“Web2Term”等标题或窗口类名判断。
- 沿实际 `owner` 关系逐级检查，排除属于受保护窗口的跨进程弹窗、对话框和菜单。最多检查 16 层；缺少程序路径、owner 不可读、循环或超出范围时，归属保持未知。
- 业务窗口发现列表不发布受保护窗口的可操作引用；未知归属的候选被排除，并使结果带 `metadata_unavailable` 和不完整状态，避免把过滤后的结果宣称为完整桌面。
- `WindowCatalog.Resolve` 使用同一入口重新读取原生身份与 owner。窗口先前曾是业务候选，随后出现受保护 owner 时，原引用被撤销；焦点、观察、控件、条件等待以及鼠标／键盘动作不能复用它。
- 启动／资源打开分发中已有自身程序保护，本项使单独 `launch_app` 也检查该保护，不允许以应用启动方式再次打开控制程序。

普通业务窗口即使标题包含“Web2Term”也不会被名称过滤。不同业务应用之间的进程切换不会因此触发控制任务中断。

桌面概览或无窗口的区域截图仍可能包含控制窗口的像素；这类观察不能直接授权输入。输入动作继续要求独立发现、有效绑定且通过即时校验的业务窗口。窗口过滤保护当前程序路径及关联 owner，不对任意重命名／复制后的程序或现有通用终端工具作沙箱承诺；终端和文件工具仍执行其原有权限与确认规则。
