# 提示词按需注入

以前，同一对话里每开始一个新任务（上一个任务以【任务完成】结束，或在弹框中手动结束），第一条用户消息都会重新带上完整的终端提示词（约 2.8k–3.8k 字），而模型上下文里其实还留着上一份。现在每个对话都有一份注入账本，每个任务开始时，在下面四种方式里选最省的一种：

| 方式 | 条件（按顺序取第一条） | 发送内容 |
| --- | --- | --- |
| 完整 `full` | 没有账本（新对话、旧对话首次使用本功能、编辑重发后）；上次完整注入后对话已累计超过预算字数；连续 2 次回复格式无法解析；变化的分段占全文 60% 以上 | 完整提示词 |
| 提醒 `reminder` | 上次完整注入或提醒后，有 1 次回复格式无法解析 | 【约定提醒】+【角色】【任务路由】【工作协议】【需要执行时】【任务完成】，以及有变化的分段 |
| 增量 `delta` | 有分段变化（执行环境、目录、用户补充、工具目录、computer use 状态等） | 【提示词更新】+ 只含变化的分段；被删掉的分段写明「已不再适用」 |
| 锚点 `none` | 以上都不满足 | 一行「【终端助手】本对话此前注入的约定继续有效。」 |

同一任务内的后续消息（回答提问等）仍然不注入，和以前一样。

完成约定适用于终端操作和普通对话：问答、解释、翻译、写作、总结、规划、分析等纯对话请求回答完毕时，最终回复也必须第一行单独写 `【任务完成】`，然后正常回答，无需额外执行命令或调用工具。仍需用户澄清、继续执行步骤或等待工具/后台结果时不标记完成。约定提醒保留完整的完成分段及其条件。

## 分段与账本

提示词按「单独成行的【标题】」切分，每段计算一个指纹（FNV-1a）。行内的【上一条命令执行结果】等标记不会切分。账本只存分段指纹和计数，不存提示词正文：

- `charsSinceFull`：上次完整注入后对话里新增的字数，包括用户消息、AI 回复、回传的命令结果、注入的增量和锚点。文本附件按字节数的一半计；每张图片（read_files 图片、computer use 截图）按 1500 字计。
- `violations`：上次完整注入或提醒后，回复格式无法解析的次数（只计实时回复）。
- 预算按平台给出：ChatGPT 和 DeepSeek 为 6 万字，Claude 为 12 万字，Gemini 为 20 万字，其他平台为 4 万字，大约是各站点上下文长度的一半，赶在开头的提示词被截断之前刷新一次。

已有对话的账本存在 SQLite settings 表中（`conversationTools:<平台和对话>:promptLedger`），重启后保留。未保存的新对话账本只存在内存中：取得对话 ID 时移到该 ID 下；离开去开新对话时丢弃，避免过期的草稿让新对话误以为已经有提示词。

只有页面确认送达、且实际注入长度与计划一致时，才提交账本：完整注入后计数清零；增量和提醒后，全部分段更新为当前指纹；锚点不改分段。长度不一致（发送时恰好换了计划）时不提交，下次继续按原计划注入。

在专注视图中编辑重发会删掉之后的所有轮次，可能也删掉了带提示词的那一轮，所以编辑前先清空账本，并等页面拿到完整提示词后再发送。定时任务的发送也使用计划好的前缀。

## 诊断日志

决策和账本变化写入 `%TEMP%\gpt-login-diag\<平台>-prompt-*.log`，只记元数据，不记提示词正文和对话内容：

- `injection-plan`：推给页面的前缀变化时记一行，包括 `mode`、`reason`、`prefixLength`、`fullLength`、`charsSinceFull`、`violations`、`budget`，以及变化或删除的分段标题。
- `injection-committed` / `injection-unmatched`：送达后提交了账本，或因长度不一致没有提交。
- `injection-violation`：记一次格式违约。`injection-reset`：编辑重发时清空了账本。
- 原有的 `injected` / `sent` 行多了 `injectionMode` 字段，记录这次发送所用的方式。

## 导出日志

「设置 → 应用更新」中的「导出诊断日志」把最近 7 天的日志打包成一个 zip：`diag/` 是 `%TEMP%\gpt-login-diag`，`app/` 是用 `DSH_APP_LOG=1` 运行时写出的应用日志，另附 `manifest.json`（应用版本、系统、导出时间、文件数）。保存后会自动在文件夹中显示该 zip。日志可能包含本机路径和对话片段。

## 用户测试

新增 `tests/prompt-injection.test.mjs`，使用真实的提示词构建函数、规划函数和内存 SQLite，覆盖：分段切分，新对话完整注入，无变化时只发锚点，工具或补充说明变化时只发增量（包括删除分段），换机器，违约提醒和升级为完整注入，预算耗尽，账本持久化，以及草稿账本的移交和丢弃。

由用户运行：

```powershell
node --test tests/prompt-injection.test.mjs tests/conversation-tools.test.mjs tests/scheduled-tasks.test.mjs tests/mail-notification.test.mjs tests/focus-edit.test.mjs
```

真实对话中的效果，需要由用户用 `npm run dev` 跑几轮多任务对话后导出日志来确认：看 `injection-plan` 的分布，以及 `none` / `delta` 之后 `injection-violation` 是否变多。交付状态为构建通过、等待测试。
