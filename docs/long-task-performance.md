# 长任务记录累积后的性能优化

用户反馈：长目标任务积累很多记录后，打开终端、专注会话以及操作整个软件都会卡顿。

本次依据代码检查定位开销，未启动 Electron、访问真实会话或执行测试。构建通过只表示代码可编译和打包，实际响应时间、CPU 和内存变化仍需用户测试。

## 定位与修改

| 路径 | 原有开销 | 本次修改 |
| --- | --- | --- |
| 专注视图轮询 | 每 900 毫秒查询全部执行历史、传输历史输出，并对整个快照做 JSON 序列化比较 | 按会话轮次和执行记录版本同步；未变化的集合不再查询或传输，界面复用已有引用 |
| 首次打开与执行状态事件 | 即便输出区域收起，仍读取和传输每条命令的完整输出；收到事件后界面再查一次相同历史 | 界面查询只取执行摘要；展开记录后读取该条输出；状态事件直接使用已有摘要 |
| 会话持久化 | 任一轮次更新，重写全部已加载轮次 | 记录发生变化的轮次，仅保存这些轮次；失败的写入保留以供重试；编辑后的归档轮次也会保存 |
| 过程分组 | 每个过程段遍历全部执行记录，另有重复的反向扫描 | 先按 cycle 建立分组，单次渲染的分组成本由 O(段数 × 执行数) 改为 O(段数 + 执行数) |
| 折叠内容 | React 仍创建收起的命令输出、思考内容和过程内容 | 展开后才创建正文；保留展开选择及过程滚动位置；待确认操作仍在输出折叠区外 |
| 终端更新引发的重渲染 | 流式输出刷新父组件，新回调使专注视图的缓存失效 | 稳定 owner 和回调引用，使用 memo 隔离专注视图 |
| 超长单条输出 | 整段文本进入 DOM 并反复更新 | 默认显示最近 32 Ki 个 UTF-16 字符，支持显示更早内容、显示全部、复制全部；不截断源数据 |
| 上下文统计 | 每条工具事件都可能再次解析同一个不断增长的轮次 JSON | 先物化关联轮次及归档列表，每个轮次解析一次；数据库无变化时复用统计汇总；缓存最多保留 32 个会话 |

增量同步的游标包含完整会话归属。展开输出也检查当前会话及被替换的历史分支，避免把另一会话的数据放入当前视图。主进程内部的执行读取默认仍返回完整数据；摘要模式仅用于界面列表和状态推送。

历史记录、输出、命令去重、确认/跳过、任务停止和回传逻辑没有通过清空或缩短记录来优化。已有的终端滚动记录上限和已加载轮次数上限保持原有设定。

## 调研依据

- [Electron 性能指南](https://www.electronjs.org/docs/latest/tutorial/performance)：主进程工作会影响整个应用的交互响应，需减少阻塞及重复处理。
- [React memo](https://react.dev/reference/react/memo)：缓存依赖稳定的 props；每次新建对象或回调会使缓存失效。
- [SQLite WITH 与 MATERIALIZED](https://www.sqlite.org/lang_with.html)：显式物化用于防止中间查询被展开而重复计算。
- [SQLite total_changes](https://www.sqlite.org/c3ref/total_changes.html) 与 [PRAGMA data_version](https://www.sqlite.org/pragma.html#pragma_data_version)：同时覆盖当前连接及其他连接造成的数据库变化，用于统计缓存失效。

## 用户执行的回归检查

本次新增或调整的回归用例可在支持 `node:sqlite` 的 Node.js 环境运行：

```powershell
node --experimental-sqlite --test tests/long-task-performance.test.mjs tests/long-task-storage.test.mjs tests/focus-chat.test.mjs tests/focus-answer-layout.test.mjs tests/focus-smart-ui.test.mjs tests/focus-model-settings.test.mjs tests/context-usage.test.mjs tests/focus-token-usage.test.mjs
```

用例检查集合复用与会话隔离、5000 个过程段的线性查找次数、SQLite 摘要与完整输出的一致性、执行状态版本、失败写入重试、归档编辑、延迟展开、Unicode 边界，以及 1000 条工具事件对应的轮次 JSON 解析次数。以上是用例的检查目标，不能视作已通过的测试结果。

本机命令行 Node.js 为 v22.12.0，需要上述 `--experimental-sqlite` 参数。精确的 JSON 解析次数计数使用 v22.13.0 起提供的 SQLite 自定义函数接口；更早版本仍检查汇总结果、缓存复用和写入后失效，并在测试日志中说明该计数未执行。

真实界面只用项目规定的启动命令，由用户操作：

```powershell
npm run dev
```

建议使用已经积累很多记录的会话，检查：

1. 在终端、专注和原始视图之间切换，比较首次打开及再次打开的响应。
2. 持续输出期间在专注视图输入，检查输入和切换是否顺畅。
3. 展开旧命令，核对命令、完整输出、退出码及回传状态；关闭再打开，检查展开记忆和过程滚动位置。
4. 对超过 32 Ki 字符的输出检查加载更早内容、显示全部和复制全部，核对首尾内容。
5. 检查待确认命令的运行/跳过、任务停止、消息编辑、文件回传、上下文统计，以及跨会话切换。

## 当前边界

本次没有真实会话的性能采样，因此不提供耗时、内存或提速百分比。初次载入仍需读取轮次和执行摘要；轮次实际变化时仍同步轮次集合。终端传输仍沿用现有快照协议，极大量持续输出的进程间传输成本未完全消除。应先用上述回归和实机操作确认效果，再根据日志或性能采样决定是否进一步拆分历史分页、轮次存储或终端传输协议。
