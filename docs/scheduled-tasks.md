# 定时任务

定时任务保存周期和自然语言任务描述，到期后由软件向创建时绑定的 AI 对话提交新任务。它使用应用内调度器，无需用户编写等待脚本、启动后台进程或配置 Windows 计划任务。

## 创建和管理

右侧页签栏的「＋」菜单新增「定时任务」。表单提供任务周期和任务描述，支持固定分钟／小时／天间隔、每天、工作日、每周和五段 Cron 表达式。日历周期同时保存 IANA 时区，默认使用本机时区。固定间隔首次在保存后的一个周期触发；创建计划不会立即执行。

当前对话的「工具设置」提供「定时任务」开关和工具提示词，默认启用。AI 可以创建、查询、修改和删除当前对话的计划；按需读取的完整说明提供调用格式、周期与时区限制、投递条件及操作回执约定。创建格式如下：

```json
{"type":"scheduled_task","schedule":{"kind":"interval","minutes":30},"prompt":"检查当前项目的后台服务状态，发现异常时分析原因。"}
```

日历周期示例：

```json
{"type":"scheduled_task","schedule":{"kind":"cron","expression":"0 9 * * 1-5","timeZone":"Asia/Shanghai"},"prompt":"检查当前项目的工作区状态，整理今天需要处理的问题。"}
```

创建时接受 `type`、`schedule`、`prompt`，也可显式填写 `action: "create"`。固定间隔为 1–5256000 的整数分钟，任务描述非空、最多 16000 字符，需写清每次触发时的任务。主机、目录、会话和平台由软件捕获，模型不能覆盖。Cron 仅接受五段表达式，不接受秒字段或随机 `H` 字段；`timeZone` 按实际任务填写有效的 IANA 时区，示例中的时区不作为工具默认值。具体表达式由 cron-parser 在主进程验证。

管理已有计划使用同一个 `scheduled_task` 工具，每次单独输出一个请求：

```json
{"type":"scheduled_task","action":"list"}
```

列表只返回当前工作区、AI 平台和对话的未删除计划，每页最多 10 条，包含真实 `id`、`revision`、启用状态、周期、描述和下次时间。存在 `nextOffset` 时，可用 `action: "list", offset: nextOffset` 继续查询。列表描述超过 1000 字符会截断并标记 `promptTruncated`；修改前可读取完整内容：

```json
{"type":"scheduled_task","action":"get","id":"查询得到的任务编号"}
```

修改时使用实际编号及版本，`prompt` 和 `schedule` 至少提供一个，未提供的字段保留。任务编号、原会话、执行主机和目录保留，原暂停状态保留，重新计算下次时间：

```json
{"type":"scheduled_task","action":"update","id":"查询得到的任务编号","revision":1,"prompt":"检查 Star 和 Fork 的变化，同时识别新增用户，邮件附上用户主页和北京时间。"}
```

删除原计划，不创建替代计划：

```json
{"type":"scheduled_task","action":"delete","id":"查询得到的任务编号","revision":2}
```

`revision` 必须来自查询或软件实际回执，示例中的数字不是默认值。版本冲突时重新查询，不能猜测或覆盖管理页的更新。AI 不能跨工作区、平台或对话修改、读取和删除计划。暂停、恢复、立即运行和投递核对继续在管理页进行。

创建及管理请求按工作区、平台、对话、用户提交和助手消息编号去重。管理变更与去重记录在同一 SQLite 事务内保存，重复扫描或重新加载不会重复修改；相同描述的不同创建请求仍可创建不同计划。删除的计划保留来源墓碑，历史回复不能将它重新创建。管理结果独立于计划本身发送，因此删除或暂停状态不阻止删除／修改回执。网页明确忙碌时只重试回执，不重复执行变更；发送结果不确定时不自动重发，可查询状态或在管理页核对。

AI 创建成功后，软件回传任务编号、版本、周期、下次触发时间和任务描述。管理操作同样以软件实际回执为准，不能在回执到达前宣称成功。回传只属于发起请求的那次原任务；切换任务或重启后不将旧工具确认注入新任务。计划一旦保存，即使确认未能回传，仍可在管理页查看。

管理页支持暂停、恢复、编辑、删除、立即运行和展开最近运行记录。立即运行只加入投递队列，不修改周期。修改后取消旧版本尚未投递的运行，保留原会话和执行目标，并重新计算下次时间。恢复计划从恢复时重新计时。关闭页签不停止计划；新建计划自动打开页签，普通状态更新不抢占页签。

## 调度和持久化

计划保存在本地 SQLite 的 `scheduled_tasks` 表，每次运行保存在 `scheduled_task_runs` 表，AI 管理请求的去重记录与结果保存在 `scheduled_task_tool_results` 表。任务定义与本次运行分开，投递记录不冒充 AI 的业务完成状态。支持 computer use 时，本次投递关联实际新任务编号。

主进程查找最近的 `next_run_at`，使用一个定时器唤醒，最长等待 60 秒。到期查询使用 `(enabled, deleted, next_run_at)` 索引。创建或变更计划、返回原工作区、取消暂停以及电脑从休眠恢复时重新唤醒检查。有待投递消息时最长每 10 秒重新检查。检查本身只访问本地状态；实际到期且满足条件时才提交 AI 消息。

到期时，在一个 SQLite 事务中登记本次运行并推进下次时间。固定间隔按原计划时间推进，不按实际发送或执行结束时间累加。错过多个周期时合并为最近一次，并记录最早错过的时间。已有周期运行仍待投递时更新同一条待投递记录，不不断堆积。人工立即运行或需要核对的运行占用该计划的未处理位置，不再创建并行运行。

每条运行使用计划、版本和发生键去重。提交前持久化 `sending`，明确成功后标为 `sent`。明确的发送前忙碌可重新排队；提交结果不确定则保留 `needs-attention`，不会自动重发。软件在发送中退出，重启后同样标为需要核对。用户核对原对话后可选择「确认已投递」或「跳过本次」。这两个操作都不重新提交消息。

单次网页投递等待最多 20 秒；页面没有响应时中止后续提交尝试，保留需要核对状态，调度器继续处理其他计划。该期限仅约束网页投递，不限制 AI 的任务执行时间。迟到回执不会据此恢复已取消的任务控制。

每个计划最多保留最近 50 条已终结运行，以及所有仍待处理的记录。工作区删除时一并删除其计划及运行记录。计划暂停、修改或删除时取消待投递记录并中止尚未确认的提交；已经发出的消息和 AI 工作不会由修改计划自动撤销，应使用现有任务停止入口处理。

## 投递与执行边界

- 必须选中原工作区、原 AI 平台和原对话，并恢复原执行主机与工作目录。不会自动切换对话、接管其他终端或更改目录。
- 终端模式、提示词注入和定时任务工具需要开启。执行目标断开时等待重新连接。
- 定时任务复用当前对话已经注入的系统和工具提示词；该对话尚未注入时，首次投递仍附加完整提示词。确认发送后按平台和对话持久化注入记录，任务结束或重启不会清除；旧对话也可从已渲染的用户消息识别完整提示词。普通手动消息继续使用原有的任务注入规则。
- 到期后直接检查发送条件，不等待当前 AI 任务被标记结束。正在发送／执行工具／回传后台结果、AI 正在生成或正在等待用户回答时保留待投递记录，发送条件恢复后重试。文字、图片及附件草稿由原发送通道保护，不覆盖。
- 暂停、全局急停和用户接管继续阻止自动投递。定时任务不会解除人工暂停或释放用户的桌面控制权。
- 每次到期提交新的目标，使用当前真实能力重新登记任务，不恢复旧任务的令牌、执行权限或工具步骤。已正常完成的目标不阻止下一周期创建新目标。
- 发送结果会写入对话与投递记录；「已投递」只表示消息发送成功，AI 是否完成、失败或等待回答要查看原对话。
- 软件需保持运行，关闭主窗口驻留托盘时调度仍可运行。退出软件或电脑休眠期间不能准时提交，启动／恢复后按合并规则处理。切走会话时不会继续无人值守操作桌面。

## 由用户运行的检查

离线回归使用真实 SQLite、周期解析、主进程方法与假时钟／假页面，不启动 Electron、不连接第三方服务：

```powershell
node --test tests/scheduled-tasks.test.mjs tests/conversation-tools.test.mjs tests/autonomous-task-entry.test.mjs tests/computer-recovery.test.mjs tests/workspace-projects.test.mjs tests/project-terminal-notes.test.mjs
```

交互检查只通过仓库约定启动：

```powershell
npm run dev
```

建议检查：

1. 在一个已有对话中，通过右侧「＋ → 定时任务」创建每 1 分钟的简单任务。确认保存时不发送，列表显示下次时间，到期只投递一次，并保存运行记录。
2. 让 AI 创建同类计划，确认工具设置能查看提示词，创建回传包含真实编号和下次时间，管理页能看到计划。确认 AI 结束本轮创建任务后，后续周期仍可提交新目标。
3. 保持当前 AI 任务未标记结束，等待网页回复完成且输入框可用；确认到期照常投递。再分别保留文字／附件草稿、让 AI 正在生成或执行工具、进入待回答问题状态；确认暂不可发送时排队，草稿保留，条件解除后只提交一次。
4. 切到其他工作区／AI 平台／对话或切换主机／目录；确认任务不误发到新位置，恢复绑定上下文后继续等待投递。
5. 检查暂停、恢复、编辑、立即运行和删除。关闭页签不停止计划；状态更新不抢占正在查看的页签。
6. 在未发送状态重启，确认计划、下次时间和待投递记录恢复。错过多次合并一次；已经确认发送的运行不重发。
7. 在发送结果不确定的情况下，确认需要核对状态和两种处理按钮；不点击任何处理按钮时不再次提交。
8. 启用 computer use 时，确认每次触发登记新任务；完成后下一周期继续生效。人工接管、暂停和急停时不自动解除控制状态。
9. 让 AI 查询并修改已有任务的描述和周期，确认沿用原编号，没有新增重复计划，管理页及时显示变化。再让 AI 删除该任务，确认列表移除、后续不再触发，AI 收到真实删除回执。
10. 检查另一对话的编号、过期版本和已经删除的编号都不能变更当前计划。AI 查询后在管理页编辑，再让 AI 按旧版本修改，确认收到冲突提示；切换对话、暂停或急停时，旧操作回执不注入新任务。

交付状态为「构建通过，等待测试」。构建不证明真实网页上的创建、消息提交或后续执行已可用。
