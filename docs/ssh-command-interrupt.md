# SSH 前台命令中断

适用入口：主终端及通过 `+` 新建的 SSH 终端中的“中断当前命令”。常驻后台任务的停止由后台任务面板单独管理。

## 原因

模型命令通过独立的非 PTY SSH 命令通道运行。只发送 SSH `KILL` 并调用 `close()`，无法保证服务器结束子进程并返回关闭回执。原实现无限等待 `close`，导致中断 IPC 一直不返回，命令卡片持续显示执行中。

## 处理

- 首条命令执行前，记录当前远端 shell 的 PID 和启动时间。身份数据使用带随机标识的内部协议行传回，不进入可见输出或 AI 结果。
- 中断通过原 SSH 连接打开独立控制通道，核对启动身份，收集当前 shell 及其子进程的 PID 和启动身份，依次请求结束；对仍存在的原进程升级强制结束，再确认进程消失或成为僵尸。
- 每次发送信号前核对启动身份；不使用进程名匹配、全局结束或进程组结束，避免影响其他终端及后台服务。
- 停止过程最多等待 10 秒，包含控制通道打开和原命令通道关闭。连续点击共享一次停止请求。
- 必须同时确认进程检查成功和原命令通道关闭，才报告“已中断”并重新创建命令会话，保留原目录。期间即使命令正常完成或主通道先关闭，也不提前释放执行位置。
- 缺失身份、确认失败或超时，立即显示错误和“终端操作 → 重置终端”的恢复路径；保留原命令的未确认状态，新指令保持待执行。重置后须检查原命令状态，再决定是否重试。
- 失败由原命令处理，不会转而向手动 SSH PTY 发送 Ctrl+C，也不会把待执行命令转到本机。
- 用户重置终端后，旧命令的迟到结果仍存入执行记录，但不会回传 AI 触发自动重试。

本改动处理用户主动中断。命令自身的执行超时、常驻后台服务的就绪超时分别沿用各自机制。

## 用户回归

智能体不运行测试或启动应用。离线回归使用模拟通道和手动时钟，不连接远端、不发送真实进程信号：

```powershell
node --test tests/remote-interrupt.test.mjs tests/ssh-directory.test.mjs tests/recent-command-run.test.mjs
```

真实 SSH 行为由用户更新并重新启动应用后确认：运行一个持续等待的命令，点击“终端操作 → 中断当前命令”；检查中断结果、目录保留和下一条命令的执行主机。关闭回执异常时，应在 10 秒后出现明确错误，且不会自动开始新指令。
