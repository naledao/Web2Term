# DeepSeek 专注对话

生产接入日期：2026-10-22。状态：已实现，构建通过后等待用户运行验收。

## 直接使用

在项目根目录运行唯一的开发启动命令：

```powershell
npm run dev
```

选择 DeepSeek，点击窗口右上角的「专注对话」。右上角始终保留三个入口：

| 入口 | 用途 |
| --- | --- |
| 原始 | 原网页，可登录、处理验证、使用网页原生附件与模式设置 |
| 本地对话 | 现有的本地聊天记录阅读视图 |
| 专注对话 | 新的输入与回答界面，将思考、检索、命令和回传归入同一轮 |

专注对话目前支持 DeepSeek。其他平台保留原始、本地对话两个可用入口。

可以直接正常聊天，无需截图、按采集阶段打点或启动额外探针。简单验收时，发送一条消息，观察回答，再切换三个视图即可。自动执行、手动确认、问题回答、结束任务等场景可以在日常操作中继续覆盖。

## 展示与操作

- 顶层只展示真实用户提问、助手回答和必要的等待或失败反馈。
- 注入的系统提示词、工具提示词、命令协议 JSON 和自动回传消息不作为聊天正文。专注视图也隐藏执行控制里的提示词入口、注入开关和注入计数。
- 一个用户发送建立一轮；随后多次命令执行和内部结果回传沿用这一轮。思考和检索按网页中的顺序放进「查看过程」，执行输出也在过程内。
- 待确认的命令、失败和回传受阻在折叠区域之外显示。执行仍通过原有手动/自动模式和执行器，不因切换视图自动批准命令。
- 模型提问时，输入区上方显示「回答问题」。点击后打开现有问题控件；底部状态栏也保留待答入口。
- 右侧面板默认收起，可通过右侧栏的展开按钮打开。专注对话顶部只显示名称，不放置「终端」「执行控制」按钮。
- Enter 发送，Shift+Enter 换行，支持中文输入法。只有确认发送成功后才清空相应草稿；不自动重发状态不明的消息。
- 可在输入框直接粘贴截图、剪贴板图片或文件，显示预览/文件卡片并可移除；「附件」按钮也支持直接选择文件。支持只发附件，以及文字与附件一起发送。每条最多 3 个附件，单个 20 MiB，合计 25 MiB。
- 附件在点击发送后交给原网页上传并确认消息，不会因粘贴自动发送。原网页存在草稿或附件时，不会覆盖；失败时保留专注草稿并提示检查原始视图。附件草稿在内存中保留，切换视图可恢复，关闭应用后不保留。
- 方形按钮是「结束当前任务」，调用现有停止模型、命令及自动执行的流程。已有内容保留。
- 视图偏好按工作区与平台保存，草稿按工作区、平台和对话保存。轮次关联单独持久化；恢复后的未完成历史显示为停止状态。

## 自动日志

专注对话会自动记录到：

```text
%TEMP%\gpt-login-diag\deepseek-focus-ui-*.log
```

日志包含发送请求的字符数、确认结果、页面是否就绪、是否存在原网页草稿、等待/生成状态、轮次数，以及当前正文长度和思考/检索片段数量。状态相同不重复写，每个文件最大约 2 MiB 后换新文件。

附件确认后的本地记录还有独立事件：`user-started` 表示建立了用户轮次，`user-captured` 记录图片来源和数量，`user-stored` 记录本地消息 ID 与实际入库图片数 `savedAttachmentCount`。专注上传使用本次发送令牌绑定的原始图片，`imageSource` 为 `provided`；原始网页的输入继续使用已有采集路径，来源为 `page`。

2026-10-22 17:50 的用户测试定位到首条附件消息的归属问题：上传日志返回 200 并完成点击，但首页创建新会话后被运行时判为 `context-changed-after-submit`，没有等到虚拟用户行挂载，导致没有 `user-message` 和专注轮次。已将工作区/平台归属与上传器的会话绑定分开：提交前仍要求原地址，提交后只允许上传器锁定的同源首个新会话，并继续等待同一发送令牌的确认。切换已有对话、平台、网页实例或取消任务仍会失效，不重发消息。

日志不记录提示词、消息正文、命令、输出、cookie 或截图。命令执行与结果回传仍可结合已有 `deepseek-command-*.log`、`deepseek-raw-send-*.log` 和 `deepseek-prompt-*.log` 定位。用户只需操作，之后由智能体读取日志分析。

## 实现与边界

发送复用页面现有的 confirmed-send 路径，将新输入视为用户消息；内部回传继续走原有 raw-send 路径。原网页保留在后台承载真实会话，视图切换不会删除远端消息。没有迁移模型服务。

页面采集只读取已挂载的助手回答和可见思考/检索，未挂载的片段不会通过自动翻页补抓；已采集内容会保留。虚拟行号仅用于当前发送期间的瞬时定位，不作为持久消息身份。2026-10-22 用户日志中的停止 SVG 路径用于区分生成与发送，站点改变结构时需要继续读日志调整。

没有可靠轮次关联的旧记录按干净的本地历史保留；不靠时间或「上一条命令执行结果」等关键词猜测并删除用户原话。此前从未采集的思考不能回溯恢复。

专注输入框工具栏增加“深度思考”和“智能搜索”，与附件按钮并列。开关读自当前原网页工具栏，
不另存一套默认值；选中态、禁用态和外部手动变更通过页面快照同步。切换只操作对应开关一次，
等待连续两次读取确认目标状态，不写草稿、不发消息，也不在未确认时自动重试。
首页没有会话 ID 时同样支持；切换对话、工作区或任务代次后，旧的操作失效。

按实测 `.ds-toggle-button` 和控件文案定位，读取原生 `aria-pressed` 等显式状态。
不把缺失属性当成“关闭”。没有明确状态时，按钮显示待确认并禁用；发送、生成、上传、执行或编辑中不能切换。
用户已运行 `tools/diag/deepseek-composer-modes-probe.cjs`，开关定位和状态规则已依据日志补齐。
界面和接口已接入不等于专注页的实际点击链路已经验收，仍等待用户运行应用检查。

## 回归文件与交付口径

以下离线测试由用户或维护者运行，智能体不执行：

```powershell
node --test tests/focus-chat.test.mjs tests/focus-page.test.mjs tests/focus-attachments.test.mjs tests/focus-upload-ownership.test.mjs
node --test tests/focus-composer-modes.test.mjs
node --test tests/deepseek-mode-probe.test.mjs
```

测试覆盖真实轮次逻辑、持久化归属、旧采样隔离、结束任务、多行发送、原生草稿保护、全部思考片段及协议过滤。使用合成数据，不启动 Electron、不访问第三方服务。
开关用例覆盖真实页面状态读取与设置方法、未知/重复控件保护、只点击一次、已选状态不反向切换、
草稿保留、状态不明不重试、页面切换失效、运行时发送互斥，以及 React 的选中/禁用/待确认展示。
探针用例包含日志暴露的“内层只有附件/发送、开关在外层兄弟区”结构、非语义控件发现、
消息与草稿不进入日志、重复采样只注册一次点击监听器，以及不依赖人工打点的可信点击记录。

`focus-upload-ownership.test.mjs` 另外覆盖首页创建会话后的运行时归属、取消/切换保护，以及确认后只记录一次原图。`deepseek-question.test.mjs` 补有新会话创建后用户行延迟挂载时仍等待确认的上传器回归场景。

智能体只执行静态语法检查及 `npm run build`。交付状态为「构建通过，等待测试」；构建通过不代表真实 DeepSeek 会话、终端闭环和视觉交互已验收。
