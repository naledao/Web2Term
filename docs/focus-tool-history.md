# 专注对话中的工具调用记录

此前“查看过程”主要展示终端命令与读文件执行记录。读取工具说明、定时任务、邮件通知走独立的处理链路，电脑操作也使用独立的任务状态，因此可能只有终端提示或任务活动，没有对应的专注对话过程卡片。

本次把这些调用关联到原会话、原用户轮次和对应过程段：

- 读取工具说明：显示请求的工具名称、读取处理结果、不可用原因及回传状态。
- 定时任务：显示创建、查询、详情、修改、删除的调用记录；创建确认回执按原始请求匹配。
- 邮件通知：显示发送结果及回传状态，SMTP 已接受但 AI 回执未确认时，仍保留发送成功这一事实。
- 电脑操作：从现有任务推进状态同步排队、执行、结果和回传状态，不重复派发动作。

记录保存在现有 `focus_turns` 的可选 `toolCalls` 字段中，无需新增数据库表。旧版本轮次仍可读取。未完成的调用在重启后显示为结果未确认或回传中止，不会从显示历史恢复执行权限。回传重试不重复执行邮件发送、计划修改或桌面动作。

界面只保存名称、简短请求信息和最多约 4000 字符的结果摘要，不复制完整工具说明、邮件正文、电脑输入参数或截图数据。记录正文延迟到展开时渲染；按过程段线性分组，并继续使用现有轮次版本更新缓存。

已经没有保存详细记录的旧调用，不能凭空补出完整执行和回传状态。此次修复开始记录后续调用，并保留新记录供会话切换及重启后查看。

## 用户测试

只由用户通过 `npm run dev` 启动应用。在一个支持专注视图、已开启相应工具的会话中，发送：

```text
请先读取 read_files 和 scheduled_task 的完整工具说明，读完后简短确认。
本次不要运行命令、读取文件、创建计划或发送邮件。
```

在“查看过程”中应看到“读取工具说明”卡片、请求的工具名称和回传状态。展开“查看调用详情”，应看到结果摘要，且回答区域不会重复显示原始工具协议。切换视图或重启应用后，新记录应仍可查看。

再让 AI 仅查询当前对话的定时任务，应出现“查询定时任务”记录。邮件、修改/删除计划和电脑操作的记录，可在用户原本需要这些动作时同步检查，无需为验证展示而额外产生副作用。

## 用户运行的回归用例

```powershell
node --test tests/focus-tool-records.test.mjs tests/focus-answer-layout.test.mjs tests/focus-chat.test.mjs tests/tool-prompt-reads.test.mjs tests/mail-notification.test.mjs
node --experimental-sqlite --test tests/scheduled-tasks.test.mjs
```

用例覆盖各类工具记录的所属轮次、去重、迟到回执、会话隔离、恢复状态、摘要边界、邮件发送与回传的独立状态、管理回执重试不重复执行，以及过程卡片和回答不重复展示。智能体只编写用例和读取用户提供的结果，不运行测试或 Electron。
