## 实现效果

用户仍只需在原入口布置任务。任务自动推进不等待用户打开进度、查看截图或确认中间动作；现有系统提示词、助手角色、工具协议、权限与确认规则保持原样。

现有任务摘要的折叠标题持续显示任务阶段、任务代次和执行机器。展开后保留完整原始目标、补充要求、运行／恢复预算、恢复检查点、必要问题与结果核对报告，并新增“动作与观察”区域。新区域沿用桌面工作区现有字体、颜色、按钮和折叠布局。

| 展示内容 | 事实来源与含义 |
| --- | --- |
| 目标、约束与阶段 | 原任务持久化记录和既有任务状态订阅；等待模型、工具执行、等待交付、必要澄清、受阻、中断和已完成分别显示。 |
| 应用与窗口 | 最近一次已校验的窗口观察，或跨应用记录中实际观察／焦点确认的窗口；显示对应时间。应用启动请求、打开请求和派发回执不能证明用户已经进入目标应用，也不宣称当前仍有焦点。 |
| 当前工具 | 当前桌面、终端或文件步骤；分别显示步骤状态、执行事实和交付状态。 |
| 最近桌面动作 | 当前任务代次的最近 50 条动作日志，时间倒序；显示动作名称、执行流程状态、是否有执行回执、回传状态及回传尝试次数。校验反馈标为“请求校验反馈”。 |
| 最近观察 | 截图／控件观察类型、采集时间、图像尺寸、已读取控件数、读取完整性与焦点状态；按需展开实际截图。所有观察均标为历史采集，不能当作实时桌面。 |
| 恢复与后台依赖 | 原任务恢复代次、检查点、是否需要新观察、恢复步数，以及最近五个已记录后台依赖的等待结果；不主动启动或重做等待。 |
| 结果与产物 | 继续展示第 35 项的核对报告、模型语义核对、未确认事项和阻塞项；产物增加“在文件夹中显示”。 |

动作列表不返回原始请求 JSON、工具输出正文、回传正文或模型内部思考，不按动作数量推算任务完成百分比。

## 读取与自动推进相互独立

`TaskActivityPanel` 根据既有任务状态变化刷新；展开且页面可见时，每次读取结束后等待两秒再读，读取不并发堆积。收起后停止轮询，页面隐藏时跳过读取，截图仅在用户展开预览后取得。另提供“刷新进度”处理临时读取故障。

新的读取入口只查询已保存的任务、动作日志和内存预览，不恢复任务协调器、不签发步骤令牌、不派发工具、不重新截图、不续期观察绑定，也不将“已查看”写入状态机。查询失败显示读取失败和已有时间戳，执行／交付流程按原规则继续。

`taskActivity` 只投影有界事实字段。动作流程的 `completed` 显示为“执行器已正常返回”；`executed` 表示有执行回执；`delivery=sent` 表示结果已确认回传，三者均不能代替业务目标完成。`dispatching`、执行未知、交付未知、失败、取消分别保留，不因停止任务而改写迟到的真实执行回执。

完整任务要求、阶段、恢复、问题与结果报告继续通过既有 `autonomousTaskChanged` 订阅提供。动作列表读取 SQLite 日志，包含主进程后来保存的执行／交付回执。历史终端和文件输出继续使用既有界面；本项展示这些工具的当前最近步骤，新增的有界动作列表用于桌面动作日志。

## 观察预览的生命周期

`WindowsObservationService` 仅在现有观察成功通过主进程独立校验后，向 `TaskObservationPreviewCache` 保存展示副本。点击、按键、滚动、拖拽和条件等待取得的有效后状态也沿用同一观察入口；无效、过期来源或校验失败的图像不会创建预览。

缓存规则如下：

- 归属为完整 `sessionId + platformId + conversationId + taskId + generation`，并记录实际来源步骤和观察编号。
- 每个任务代次只保留最近一份观察；新的纯控件观察替换旧截图，不将旧图冒充为新观察。
- 预览副本自记录起 15 分钟有效，读取不续期；全局最多 16 份、32 MiB 图片字节，单图最多 8 MiB，超限按最旧记录清理。
- 仅保存内存副本，不新增截图文件、图片数据库字段或图片日志。传给模型的临时附件按原流程清理后，展示副本可在自己的有效期内继续查看。
- 解绑原工具和退出时清理所属缓存。重启、过期或清理后显示观察缓存不可用，不为补齐展示而调用 helper。
- 展示缓存不参与点击定位、焦点授权、坐标有效性或模型结果交付。查看预览不能复活已失效的输入绑定。

预览 IPC 只接受任务归属和主进程已知的 `observationId`；返回已校验图像副本的 PNG data URL，不接受渲染进程提供的本地路径或任意网络地址。

## IPC 归属与异步隔离

| 通道 | 参数 | 行为 |
| --- | --- | --- |
| `autonomous-task:activity` | 完整任务归属 | 只读任务事实、最近 51 条日志并投影最多 50 条，额外一条用于判断是否有更早记录；只返回对应执行机器的动作。 |
| `autonomous-task:observation-image` | 完整任务归属、`observationId` | 读取对应任务最近观察的有效预览。 |
| `autonomous-task:artifact-reveal` | 完整任务归属、`evidenceId` | 复核原报告中的文件证据后，在系统文件夹中定位文件。 |

通道仅向客户端主界面主 frame 开放。参数必须是约定字段，拒绝路径、额外令牌等字段；主进程再核对当前运行实例、可见平台、真实对话和数据库内最新任务的编号／代次。停止、中断或完成后的当前任务仍可查看，但读取不会恢复执行。

组件按完整归属创建独立实例；收起、切换任务／代次或更新观察后，旧的异步读取不能更新新视图。原任务的截图不能凭相同观察编号跨会话取得。

## 产物入口

“在文件夹中显示”只接受 `evidenceId`。主进程从当前任务的核对报告找到文件条目，再与原文件证据的路径、大小和 SHA-256 一致性核对；通过已有 `recheckCompletionFile` 复读实际文件后，再次确认当前任务和报告未变化，最后调用 `shell.showItemInFolder`。

渲染进程和模型不能指定新路径。文件变化、删除、迁移、链接异常、归属变化或校验期间切换任务时，提示原因并保留报告中的保存位置。入口只定位文件，不启动产物程序，不改变任务完成状态，也不触发模型工具请求。
