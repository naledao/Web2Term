# 后台任务

后台任务登记成功后，右侧自动打开并选中「后台任务」页签；侧栏折叠时会展开。右侧「＋」菜单也提供该入口。关闭页签不终止任务或停止日志观察；日志、状态和通知发送进度更新不会反复抢占当前页签，下一次新建任务时才再次打开。

## 登记协议

模型仍然通过原有 command JSON 请求执行启动命令。启动命令成功创建后台进程后，单独打印一行：

```text
__W2T_BACKGROUND_TASK__{"pid":12345,"name":"开发服务","log_path":"/absolute/path/service.log","stderr_path":"/absolute/path/service.err","exit_code_path":"/absolute/path/service.exit"}
```

- PID 必须来自本次实际启动的进程；12345 只是格式示例。
- `name` 和 `log_path` 必填；日志路径必须是执行机器上的绝对路径。
- `stderr_path` 可选。stdout/stderr 合并时只提供 `log_path`；Windows 的 Start-Process 分别重定向到两个日志文件。
- `exit_code_path` 可选。后台任务结束后向该文件写入整数退出码，软件才能区分完成和失败。进程消失但没有退出码时显示「已结束」，不会当作成功。
- 每次新启动使用独立日志和退出码文件，日志采用 UTF-8。
- 启动命令打印登记行后返回；后台任务必须脱离当前终端生命周期。
- 标准输出格式中，标记与 JSON 位于同一行。兼容两次 `Write-Output` 形成的「标记独占一行、下一行紧跟完整紧凑 JSON」；不会跨过空行或普通日志寻找 JSON，也不会拼接不完整的 JSON。
- 只解析实际执行结果中的完整登记行，不从模型聊天文字或旧的执行历史自动登记。

任务绑定执行启动命令时的本机、SSH 主机或 Web2Term 设备。观察使用独立 Shell，不占用模型的主终端。约每 4 秒读取一次状态和日志；同一目标的读取串行执行，文件未变化时仅返回元数据。断线或切换设备后显示「状态未知」，恢复原连接后重试。进程启动标识变化时将原任务视为已结束，防止 PID 复用。

## 等待与自动回传

登记成功后，软件保留启动命令的执行记录，向原平台、原对话发送一次「【后台任务已创建】」，包含任务名、PID 和日志路径。消息明确说明已由软件接管监控、创建成功不代表任务完成，要求模型简短确认后等待，不再发送轮询命令。软件独立等待任务结束，再多读取一次最终日志，然后发送一次「【后台任务执行结果】」，包含状态、退出码、日志路径和有长度限制的 stdout/stderr。普通启动输出不另外发送。

页面正在生成、存在文字或附件草稿、正在等待用户回答、自动化已暂停、终端模式关闭，或者对话、执行主机已切换时，创建确认和结束结果分别排队。恢复原对话和执行目标且页面空闲后继续尝试。两种通知独立去重；即使任务很快完成，也先发送创建确认，再等待页面空闲发送结束结果。提交结果不确定时停止自动重试，在后台任务页显示需要处理的提示。用户主动结束任务会取消该轮任务的自动回传，观察记录和后台进程仍保留。

基础系统提示词的「执行方式」保留简短的选择规则：预计超过 2 分钟、持续输出、等待外部事件或需要脱离当前终端运行的非交互任务，使用 `background_task`；短时、一次性命令直接执行。后台任务的具体启动、登记格式和等待约定位于「查看工具提示词」的 `background_task` 工具说明中。Web2Term 也启用后台任务工具说明，同时继续关闭不支持的 `read_files` 工具。

工具提示词按「启动 → 登记 → 等待结果」精简，只保留调用所需的约定和一个 JSON 示例。使用时机保留在系统提示词，菜单位置、排队机制和观察过程等实现说明保留在本文档。这个分工参考 [OpenAI 工具描述建议](https://developers.openai.com/api/docs/guides/function-calling#best-practices-for-defining-functions)中对调用时机、参数格式与返回含义的要求，以及[提示词编写建议](https://developers.openai.com/api/docs/guides/prompt-generation)中清晰、具体、删去不必要指令的原则。

## 当前范围

- 本轮运行期间保留任务记录；切换模型或工作区不会丢失同一工作区的后台任务。关闭应用或删除工作区后不恢复任务列表。
- 关闭应用只释放观察通道；脱离终端的后台进程及日志文件由其自身生命周期决定。
- 页面分别展示 stdout/stderr 的最新 64 KiB，超出时提示截断；完整输出仍在日志文件里。支持跟随输出和手动滚动阅读。
- 已结束的任务收进可展开的历史列表，详情页保留日志。
- Web2Term 的独立观察通道占用一个设备终端名额；设备已有 3 个活动终端时，会显示通道不可用原因，释放名额后自动重试。同一工作区内的多个后台任务共用观察通道。
- 模型收到一次创建确认和一次最终结果；运行过程只在后台任务页更新，不持续向模型发送日志，也不需要模型轮询。本功能不新增停止或重启后台进程的操作。

## 由用户运行的检查

离线回归（假 Shell、假定时器，不启动 Electron 或真实进程）：

```powershell
node --test tests/background-tasks.test.mjs
node --test tests/background-task-results.test.mjs
node --test tests/background-task-panel.test.mjs
node --test tests/recent-command-run.test.mjs
```

本机 Shell 的日志读取检查（临时文件和测试进程自己的 PID，不启动 Electron、不连接网络）：

```powershell
node --test tests/background-task-shell.test.mjs
```

交互检查通过项目约定命令启动：

```powershell
npm run dev
```

建议开始一轮新任务，让模型执行一个明确允许放后台的短任务，例如「启动一个后台任务，每秒向日志追加一行，共写 20 行；按后台任务工具协议登记真实 PID、日志路径和退出码文件，结束后由软件自动回传结果」。检查：

1. 默认页签栏没有「后台任务」，「＋」菜单内有该入口。
2. 页签未打开时启动任务，自动打开并切换到「后台任务」，折叠侧栏时也会展开，列表能看到任务和真实 PID。
3. 点击任务能看到日志追加；标准输出、错误输出分别可查。查看日志时主终端仍能执行其他命令。
4. 从「＋」重复点击只选中已有页签；关闭再打开能继续查看同一任务。
5. 有退出码文件的成功／失败任务显示相应状态；没有退出码文件的进程退出显示「已结束」。
6. 多任务的日志相互独立；本机和 SSH/Web2Term 各检查一次。切换主机后旧任务显示未知状态，恢复原连接后继续读取。
7. 登记成功后，原对话自动收到一次「后台任务已创建」，模型只简短确认并等待。结束并读取最终日志后，再收到一次「后台任务执行结果」，包含最后输出和真实退出码。运行期间不重复发送状态通知；用户关闭页签后日志刷新不把它重新打开。
8. 运行中或排队时暂停，或者在网页输入框保留草稿；完成结果等待，不覆盖草稿。恢复并清空草稿后自动发送。切到其他对话不会收到原任务的结果，回到原对话后继续发送。
9. 手动结束任务后，即使后台进程稍后退出，也不重新唤醒 AI。关闭后台任务页签则仍保留监控和自动回传。
10. 基础系统提示词包含何时使用后台任务的「执行方式」规则，不包含登记字段和协议示例；工具提示词显示 `background_task` 的具体约定，登记 JSON 以代码块展示。

本功能的交付标准为「构建通过，等待测试」。上述离线回归和交互检查由用户执行。
