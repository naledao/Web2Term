# 后台任务

右侧「＋」菜单提供「后台任务」入口，按需打开单个可关闭页签。后台任务自动登记，登记时不会打开或切换页签。关闭页签不终止任务或停止日志观察。

## 登记协议

模型仍然通过原有 command JSON 请求执行启动命令。启动命令成功创建后台进程后，单独打印一行：

```text
__W2T_BACKGROUND_TASK__{"pid":12345,"name":"开发服务","log_path":"/absolute/path/service.log","stderr_path":"/absolute/path/service.err","exit_code_path":"/absolute/path/service.exit"}
```

- PID 必须来自本次实际启动的进程；12345 只是格式示例。
- `name` 和 `log_path` 必填；日志路径必须是执行机器上的绝对路径。
- `stderr_path` 可选。stdout/stderr 合并时只提供 `log_path`；Windows 的 Start-Process 分别重定向到两个日志文件。
- `exit_code_path` 可选。后台任务结束后向该文件写入整数退出码，软件才能区分完成和失败。进程消失但没有退出码时显示「已结束」，不会当作成功。
- 每次新启动使用独立日志和退出码文件，日志采用 UTF-8。
- 启动命令打印登记行后返回；后台任务必须脱离当前终端生命周期。
- 只解析实际执行结果中的完整登记行，不从模型聊天文字或旧的执行历史自动登记。

任务绑定执行启动命令时的本机、SSH 主机或 Web2Term 设备。观察使用独立 Shell，不占用模型的主终端。约每 4 秒读取一次状态和日志；同一目标的读取串行执行，文件未变化时仅返回元数据。断线或切换设备后显示「状态未知」，恢复原连接后重试。进程启动标识变化时将原任务视为已结束，防止 PID 复用。

## 当前范围

- 本轮运行期间保留任务记录；切换模型或工作区不会丢失同一工作区的后台任务。关闭应用或删除工作区后不恢复任务列表。
- 关闭应用只释放观察通道；脱离终端的后台进程及日志文件由其自身生命周期决定。
- 页面分别展示 stdout/stderr 的最新 64 KiB，超出时提示截断；完整输出仍在日志文件里。支持跟随输出和手动滚动阅读。
- 已结束的任务收进可展开的历史列表，详情页保留日志。
- Web2Term 的独立观察通道占用一个设备终端名额；设备已有 3 个活动终端时，会显示通道不可用原因，释放名额后自动重试。同一工作区内的多个后台任务共用观察通道。
- 本次没有新增停止、重启任务或自动向模型推送后台日志的功能；模型原有的有界状态查询约定继续生效。

## 由用户运行的检查

离线回归（假 Shell、假定时器，不启动 Electron 或真实进程）：

```powershell
node --test tests/background-tasks.test.mjs
```

本机 Shell 的日志读取检查（临时文件和测试进程自己的 PID，不启动 Electron、不连接网络）：

```powershell
node --test tests/background-task-shell.test.mjs
```

交互检查通过项目约定命令启动：

```powershell
npm run dev
```

建议让模型执行一个明确允许放后台的短任务，例如「启动一个后台任务，每秒向日志追加一行，共写 20 行；按后台任务协议登记真实 PID 和日志路径」。检查：

1. 默认页签栏没有「后台任务」，「＋」菜单内有该入口。
2. 页签未打开时启动任务，当前页签不被切换。随后从「＋」打开能看到任务和真实 PID。
3. 点击任务能看到日志追加；标准输出、错误输出分别可查。查看日志时主终端仍能执行其他命令。
4. 从「＋」重复点击只选中已有页签；关闭再打开能继续查看同一任务。
5. 有退出码文件的成功／失败任务显示相应状态；没有退出码文件的进程退出显示「已结束」。
6. 多任务的日志相互独立；本机和 SSH/Web2Term 各检查一次。切换主机后旧任务显示未知状态，恢复原连接后继续读取。

本功能的交付标准为「构建通过，等待测试」。上述离线回归和交互检查由用户执行。
