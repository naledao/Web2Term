# 第 30 项：动作去重与防止历史重放

本项为 computer use 增加独立的 SQLite 接纳登记表 `computer_action_claims`。动作进入全局桌面队列之前，任务步骤与完整请求登记必须在同一事务中提交；执行器调用前仍先保存原有步骤执行状态。模型重复上报一个回答、页面节点重挂载、传输编号改变或旧步骤令牌再次出现，都不能再次派发原操作。

保持现有系统提示词、助手角色、computer／终端／文件／后台工具 JSON 协议和自动／手动确认规则。页面代次属于客户端传输元数据，不要求模型增加字段或生成去重 ID。

## 识别一次实际步骤

| 信息 | 来源及用途 |
| --- | --- |
| `execution_id` | 客户端生成的 UUID，复用原步骤 `step.id`；结果中的 `step_id` 与该登记一一关联 |
| 任务归属 | 主进程提供 session、platform、conversation、task、generation 和 machine；不同目标、代次及机器不能借用旧授权 |
| `source_message_id` | computer 页面扫描器按一次确认发送后的回答回合生成；与原目标发送编号、页面任务代次及路径一起复核，不使用 DeepSeek 虚拟列表行号作为持久身份 |
| `grant_token` | 本次由主进程消费的有效步骤令牌，同一任务代次中只允许登记一次 |
| `received_token` | 从实际请求读取的有效格式令牌；缺失／损坏时记 null。协议错误反馈同样登记，但不授权桌面输入 |
| `request_json`、`request_hash` | 保存规范排序的完整调用／错误反馈及原页面收据，包含参数、原始 JSON 和来源元数据；SHA-256 校验保存内容。超过上限的输入仍按原协议拒绝执行 |

唯一约束分别覆盖“同任务代次的回答回合”和“同任务代次已消费的令牌”，主键覆盖执行 UUID。相同身份下即使请求内容变化，也不能替换登记或重新执行。请求指纹用于保留及核对完整请求，不作为全局内容去重键；同样的观察、点击或输入参数，出现在另一个真实步骤、使用新令牌时可以再次执行。

原有任务消息去重、步骤令牌、严格协议校验、观察授权、全局桌面协调与结果发送确认继续生效。登记表不复用 `executions.command`，不把 computer 请求转换为终端命令。

## 派发前的顺序

1. 页面先确认当前回答来自真实的新发送，并经过原有历史基线、最终回答范围和稳定读取检查。虚拟行位置只用于该次发送的新旧边界。
2. 主进程桥接层核对平台、来源、路径、页面任务代次及文档代次；SessionRuntime 再校验目标发送编号与任务归属，重新解析原始 JSON。
3. 在构造协议反馈或暂存快速后续请求之前检查已登记的回答／令牌。旧请求直接作为重复上报接收，不执行、不再发送旧令牌错误反馈，也不消费当前新令牌。
4. `TaskProgression` 在接纳时再次检查；`TaskCoordinator` 消费令牌时生成完整登记，与 queued／not_executed 的任务步骤在同一 `BEGIN IMMEDIATE` 事务中保存。
5. 数据库写入失败、登记不匹配或唯一约束冲突时回滚整个事务，停止该次接纳，不调用执行器。之后才进入第 27 项桌面队列，并在真正派发前保存 executing 状态。

登记为不可覆盖的接纳事实，不是可恢复的命令队列。结果发送遇 busy／no-composer 时仍只重试保存的结果，不再次登记、消费令牌或执行动作。结果未知、任务取消或目标替换后，原登记仍保留；不会删除登记来使旧动作再次获得执行机会。

## 刷新、历史与迟到事件

`ChatGptEmbed` 为每个文档签发随机 `computerPageEpoch`，随客户端配置交给页面，并由 computer 事件回传。完整主框架导航／刷新开始时立即更换代次，通知 SessionRuntime 将旧自主目标中断，从而撤销其后续派发与自动回传；已经派发的动作仍按原执行事实和第 27 项退场规则处理。

即使刷新后 URL 完全相同，旧页面的迟到事件也因文档代次不同被拒绝。新配置切换文档代次时，页面清理旧的等待回答和延迟识别回调，不重新激活原历史回答。首次发送建立会话的 SPA 路由变化保留原绑定规则，不当作一次完整页面刷新。

打开历史、重新安装拦截器、旧“继续／检查”入口及客户端重启，都不从登记表恢复授权。原有任务恢复仍标记为 interrupted，进程内令牌和执行循环不会由 SQLite 记录重建。历史快照缺少新增文档代次时仍可读取，但真实页面的 computer 事件必须带当前代次。

本项提供接纳去重和历史重放防护，不能承诺崩溃场景的严格 exactly-once：操作可能已经生效，而最后状态尚未落盘。[第 31 项](deepseek-computer-use-action-states.md)已接入独立动作／观察记录和执行／交付状态；异常退出后的统一 unknown 分类及重新观察恢复，继续由第 32 项实现。
