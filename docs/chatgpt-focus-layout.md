## 读取和显示

在已知助手消息的 DIL 根下，读取没有单选组的最外层布局容器。嵌套卡片保留在同一棵树里，
避免把侧栏和功能区拆成互不关联的块。单选组仍由原有交互适配器处理，已知图表仍使用原图表通道。
普通回复也使用 DIL 和 `Text` 组件；仅有这些标记时不生成布局树，段落、行内代码与标点继续按 Markdown 读取。
无边框布局要求容器具有 Grid 或横向 Flex 排列，且至少包含两个可见的内容子项；只提取实际布局组，保留周围正文。
完成回复开头的“【任务完成】”属于协议标记，专注正文会移除它，包括加粗或标题形式；引用及代码示例中的文字保留。

无边框列表与带边框布局独立发现：在 DIL 内识别至少两行“图标 + 文字”的纵向组，
仅把行及其间的分隔线纳入该组，保留外部章节标题、引言和后续表格的位置。
列表嵌在工作台内部时随外层布局读取，避免重复；单选组内部不会被当成展示列表。
空 Divider 的细线高度和主题化背景色一并保留，不要求原网页一定使用 border。
分隔器的上下 padding 只留空，不着色：renderer 使用 1px 内容高度、`content-box` 盒模型和
`background-clip: content-box`。既有日志第 346 行的 Divider 占高 17px、上下各 padding 8px；
若丢失该绘制边界，留白也会变成粗色条。修正同时作用于已保存的空细线节点。

正文加粗也需要读取 DIL 语义。既有日志第 346 行的 node-147、node-161 等使用
`span[data-d-default-strong]`，计算字重为 600；只识别 `<strong>` / `<b>` 会丢失这些强调。
普通 Markdown 读取现在保留该标记及原生 `Text` 的 600 以上字重，覆盖整段和句中强调；
保留段落边界，避免父子粗体重复包裹，表格单元格同样保留内联强调。

保留受限的 Flex/Grid 排列、列比例、间距、边框、字号/字重、固定侧栏宽度和 SVG 几何。
可伸缩容器不复制网页的测量像素宽度；网格列转为比例，适应专注区域宽度。
文本、背景和边框映射到专注会话的主题变量。窄窗口内保留可读的示意宽度并局部横向滚动，
溢出时显示提示，支持键盘聚焦与滚动，不把整段对话撑宽。
图标列表另标记为 `kind: "list"`，不套用工作台画布的最小宽度；正文随可用宽度换行，
图标保持固定大小，保留原生行内间距与标题字重，不添加外围卡片边框。

布局序列化为 `focus-layout` 标记及可读文字后备内容；专注组件在原位置替换二者。
已有纯文字历史可通过原网页已载入回答的 `smartReplies` 恢复布局；复制回答去掉标记、保留文字。
每次快照复用同一条回答的序列化结果，避免在布局读取和普通回复读取中重复计算样式。
富内容同步与普通回复使用同一套协议过滤，指令、提问、文件读取请求不会通过此入口回填正文。
显示层保留命令段的空答案语义，并按执行消息身份排除旧指令；命令及输出仍可在执行过程展开查看，复制回答只包含正文。

只重建展示元素和 SVG 几何，包含白名单标签、样式和属性。图片仅接受已在对应回答中出现的
HTTPS 图片地址，卡片链接仅接受 HTTP/HTTPS；没有原 HTML、事件处理器、CSS URL、iframe、
脚本或外部 SVG 引用。输入控件只显示 placeholder，不复制其 value；其它未适配控件只展示
原外观。真正的单选交互仍使用既有原生点击通道。
页面提取和 renderer 解析均限制深度、元素数、文字及序列化长度；超限或不支持的数据保留文字后备。

## 2026-10-28：内存指标与进度条

用户截图中，原始视图包含“物理内存使用率”标题、16.7% 绿色进度条和三列内存指标；
专注视图缺少进度条，绿色数值变成了强调色。代码中无边框布局主要通过横向 Flex/Grid
发现，空盒子没有文字，CSS 提供的宽高也没有进入通用展示树；彩色文字则统一映射为强调色。

读取器增加短条形展示识别：原生 `progress` / `meter`、带 ARIA 进度语义的容器，以及带背景轨道
和单个填充块的空 DIL 盒子。优先使用原生数值计算比例；没有数值时读取轨道和填充块的计算宽度，
支持纯水平平移矩阵表示的填充量。渲染时只重建本地轨道和百分比宽度，不回放原始 transform。
标题、进度条、指标行三部分的容器整体提取；独立进度条也能在原位置保留，文字为空不会被丢弃。
该类指标使用 `kind: "metrics"`，不套用工作台的 560px 画布最小宽度。

文字与填充色保留成功、警告、危险三类颜色，并提供浅深色主题下的颜色和淡背景；普通蓝紫色
继续使用强调色。原有分隔线仍使用一像素绘制规则，带进度语义的细条不会被误当作分隔线。
新增属性仅允许进度条角色、短标签和有限数值，样式仅增加 `overflow: hidden` 和主题色标记。

本次依据截图和代码补充适配，没有采集该会话的新 DOM。回归用例由用户运行，涵盖 0%、16.7%、
100%、CSS 尺寸、原生数值优先、平移填充、颜色映射、正文/表格边界与解析拒绝条件。
真实验收时重启开发进程，打开截图会话并切换专注对话，对比进度条比例、绿色数值和三列指标；
再检查深色主题、窄窗口、刷新后的恢复，以及复制回答没有机器标记。

## 2026-10-28：网站参考图片卡片

用户后续截图中的 Linear、Raycast 参考卡片在原始视图中有官网预览图，在专注视图中只剩
两条浅色圆角背景及标题、说明。代码中的 `ignored` 集合明确包含 `img`，图片所在的容器因
失去图片而塌缩；渲染窗口 CSP 的 `img-src` 也未允许 HTTPS 图片，因此只增加图片标签仍不能显示。

读取器现在在已知回答的 DIL 布局范围内保留图片、`figure` / `figcaption` 和卡片链接。
图片优先使用浏览器实际选中的 `currentSrc`，其次读取 `src` 和懒加载 `data-src`，相对地址
按原页面解析。提取显示比例及 `object-fit`，将绝对定位图片还原为正常文档流中的响应式图片，
保留圆角和裁剪边界。图片不再参与空进度条识别，纯图片布局也不受“文字为空”过滤影响。

两至六列、每列包含图片的布局使用 `kind: "gallery"`，跟随专注区域宽度显示；容器窄于 560px
时改为单列。图片加载失败时保留区域并显示说明，不再只留下无内容的细条。标题链接通过
`noopener noreferrer` 在外部浏览器打开；普通来源链接内部的 Flex 不独立提取成展示布局，
避免把来源文字展开成额外的展示块。正文、来源链接和前后章节仍按原顺序保留。

解析器限制每个布局最多 12 张图片，只放行 HTTPS 图片地址及短替代文字，拒绝本地、脚本、
数据及跨分区 blob 地址，不拷贝 `srcset`、事件或任意属性。图片请求使用 `no-referrer`；
渲染窗口仅在 `img-src` 增加 HTTPS，脚本、连接和 iframe 限制保持原值。没有图片下载、
截图或自动探针；登录保护或失效的图片地址仍可能无法从专注窗口加载，应在用户真实会话中验收。

新增用户运行用例覆盖两张官网预览图、比例、裁剪、链接、说明、纯图片布局、懒加载地址、
图片与进度条区分、来源边界、窄幅样式和 CSP，以及 URL/属性/数量限制。
