# ChatGPT 专注会话：单选交互组件

支持用户操作探针实测到的 DIL 单选卡片：标题、说明、单选项和原生操作按钮。
卡片在回答原位置显示，选中值由原网页提供；本地表单支持 Tab、方向键、空格和按钮提交。
沿用专注会话的浅深色主题，长选项换行，切换中、提交中及失败状态在卡片内反馈。

## 接入方式

页面适配规则只启用在 ChatGPT，使用上述实测属性，不依赖构建生成的 CSS 类名。
读取原生 DOM 的文字、选项 value、选中与禁用状态，不读取或执行 React 私有对象和模型生成代码。
回答序列化使用 `focus-ui` 数据标记和可读引用后备内容；本地只渲染经过形状、数量、长度验证的
纯文本与原生单选/按钮控件，不回放 HTML、脚本或样式字符串。

页面快照同时携带已载入历史组件的最新回答，供旧的本地纯文本记录原位恢复卡片；
更新后的选中项不被已保存的旧回答覆盖。标记随正常回答保存，复制回答时去掉机器标记、保留选项说明。
只有对应组件仍在当前原网页里载入时才允许交互；未载入时保留可读内容和「查看原始组件」入口。

切换单选项只点击一次原生选项，等待原生 `aria-checked` 确认，并留出状态处理时间。
卡片操作由页面生成一次性点击票据，主进程通过 Electron 鼠标输入点击；不使用合成 DOM 点击。
提交按钮只点击一次原生按钮，由 ChatGPT 自己发送状态快照及新消息，不重放探针中的 API。
共享的被动请求监听器核对当前视图、会话、父消息及真实用户消息，单独记录组件状态是否一致。
要求可信点击命中目标控件且新原生用户 ID 出现在页面，才使用请求中的真实用户文字建立专注回合。
不会猜测按钮生成的消息或自动重试。

从旧卡片再次提交时，保留该助手回合，仅在确认发送后替换其后的本地消息和回合；旧记录保留归档。
页面有草稿、历史编辑框、上传、生成或等待用户回答时不会操作组件。
来源 ID、组件位置、选项及按钮文字的签名在点击前重新核对，过期组件不能点击别处。

## 2026-10-24：回复已结束仍被判忙

用户运行产生的 `chatgpt-reply-2026-10-24T12-27-08-379Z-12344-1.log`：
第 43 行在 12:28:15.453Z 清除等待（`non-command-reply`、`awaitingReply: false`）；

同时 `stopButtonFound: false`。整个任务继续等待用户选择，不代表模型仍在生成。
对应 `chatgpt-focus-ui-2026-10-24T12-27-09-190Z-12344-1.log` 第 15 行也显示
`waiting: false`、`generating: idle`、`nativeDraft: false`，文件中却没有智能 UI 请求日志。

原因是主进程入口用了导航切换所用的 `taskRunning()`：只要任务没有明确完成，就在页面点击前返回
`busy`。修复后保留任务生命周期，只用发送锁、修改锁、实际命令/结果回传、附件传输和待回答问题
作为主进程拦截条件；页面仍独立检查生成、等待、原生文字/附件草稿和历史编辑框。
不会通过强制结束任务来放行卡片，也不会因为自动执行暂停或终端模式关闭而误判有操作正在执行。

请求日志在主进程忙碌检查之前写入，并记录 `taskOpen`。早退日志带固定原因，例如
`send-in-progress`、`command-in-flight`、`question-pending`；页面返回阶段和固定原因，
例如 `awaiting-reply`、`model-generating`、`text-draft`、`attachment-draft`、`history-edit-draft`。
选项确认和新用户消息确认也分别记录，仍不保存选项值或消息正文。
