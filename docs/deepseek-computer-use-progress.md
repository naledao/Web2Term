# 第 34 项：运行统计与诊断信号

computer use 的“运行上限”设置及对应执行限制已删除。客户端不再按任务时长、单步执行时长、条件等待总预算、任务步骤数、同动作重复次数、相同观察提示阈值、连续超时次数或诊断恢复步骤数停止或拦截任务。

## 当前行为

computer use 开关与结果回传间隔已移入“查看工具提示词”弹框，按对话保存，详见 [按对话管理工具](conversation-tools.md)。任务概况保留真实工具步骤与执行状态，不再显示运行预算。旧的 `computerUseLimits` 设置不再读取、校验或写入。

`TaskCoordinator` 记录步骤和实际运行时间，但不设置任务截止定时器。暂停和等待用户回答的时间仍不计入运行统计。`TaskProgression` 不再创建额外的单步取消期限，也不按重复动作或恢复计数拦截新的模型请求。同任务终端命令使用其自身的执行时限，不再被 computer use 的预算缩短。

具体 `wait_for` 请求的 `timeout_ms`、终端命令原有时限、Windows helper 的响应监督和取消机制继续由各自工具管理。这些工具回传的实际超时仍作为诊断事实记录，不再累计成任务停止条件。

## 语义指纹与可观察状态

每次接纳新的 computer 请求时，对动作名称、目标和参数生成 SHA-256 指纹。新的步骤令牌、消息编号、时间戳或 observation_id 不等于新的状态证据。控件重新编号时使用最近真实控件的语义散列，窗口关联其完整身份，应用关联已发现的可执行路径和名称。

状态摘要读取真实执行器结果：图像散列、窗口身份、控件属性、应用和窗口列表，以及当前文件步骤的实际读取快照。仅保存有界散列索引和计数，不复制控件正文、输入文字或图像字节。实际证据变化开启新的观察阶段；动作成功或命令退出码 0 本身不证明业务目标完成。

重复动作、同来源相同观察、原生执行超时和条件等待超时写入 `computer_result.progress_control`。这些字段只提供统计和诊断线索，由模型结合实际后状态选择下一步；没有硬停止标记或剩余预算。

## 派发、取消与交付

同一条模型回答或旧步骤令牌仍不能重复执行。新的有效请求可以再次选择同一动作，客户端不再以缺少进展或次数达到阈值为由拒绝派发。

用户结束任务、全局急停、会话失效和必要澄清仍沿用原有流程。取消请求发给实际执行器，桌面凭据保持到执行器真实退出；迟到结果只补充原任务历史，不恢复已停止目标。

结果交付重试复用已保存的正文，不重复动作、观察或执行计数。发送未知仍需核对；移除运行上限不会把未知执行或未知交付伪装为成功，也不改变现有任务完成规则。

## 旧任务兼容

进度状态使用版本 2，保留执行统计、语义散列和待执行步骤的归属，不再保存 `limits`、`halted` 或派发前的硬停止标记。

读取版本 1 检查点时，丢弃旧上限及其停止标记，保留已知步骤数、实际耗时和执行事实。旧任务可以通过用户发起的“恢复原任务”接续，仍先重新观察；打开历史或升级客户端不会自动执行。

若回执已落盘而任务检查点更新失败，启动恢复仅补回匹配任务、代次和步骤的真实统计。旧回执中的上限停止标记不会重新阻止恢复。
