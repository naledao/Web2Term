# 邮件通知设置

提供个人 QQ 邮箱的发件配置和默认收件邮箱设置。入口：应用的「设置 → 邮件通知」。

## 默认收件邮箱

- 在「默认收件邮箱」中填写一个完整的 `@qq.com` 地址，点击「保存收件邮箱」。
- 收件邮箱独立保存，无需先配置发件邮箱或 SMTP 授权码；可以与发件邮箱相同。
- 保存后关闭并重新打开设置、重新启动应用，均可读取已保存的收件地址。
- 保存时去除首尾空格并统一为小写；拒绝其他邮箱域名、多个地址、邮件头注入及格式错误。
- 「清除收件邮箱」只移除默认收件地址；「清除发信配置」只移除发件地址与授权码。
- 收件地址保存在本地数据库的独立配置项 `qqMailRecipient` 中，保存和清除均不联网、不发送邮件。
- AI 的 `send_email` 工具使用此地址作为收件人。

## 发信配置

- 仅接受 `@qq.com` 发件地址。
- SMTP 服务器固定为 `smtp.qq.com`，端口 `465`，使用 SSL/TLS，校验证书。
- 填写 QQ 邮箱生成的 16 位 SMTP 授权码。
- 「保存配置」立即保存，无需重新加载应用。保存本身不连接 QQ 邮箱。
- 同一邮箱的授权码留空可保留原值；更换邮箱必须同时填写新授权码。
- 「测试连接」检查当前输入的连接和 SMTP 登录，不保存配置、不发送邮件，不自动重试；总超时为 20 秒。
- 「清除发信配置」移除本机保存的发件地址及授权码。

QQ 邮箱的服务开启及授权码生成步骤见[官方说明](https://help.mail.qq.com/detail/106/985)。在网页版中进入「设置 → 账号与安全 → 安全设置」，开启 POP3/IMAP/SMTP 服务并生成授权码。

授权码通过 Electron `safeStorage` 加密，和发件地址一起写入本地数据库的单个配置项。读取接口仅返回邮箱、授权码存在状态及可读状态，不返回授权码或密文。系统加密不可用时拒绝保存；Linux 的 `basic_text` 后端不视为安全存储。SMTP 原始错误不回传界面，避免服务端返回内容带出敏感信息。

SMTP 登录检查成功不代表实际投递成功。AI 发信能力见下方工具说明。

## AI 邮件通知工具

在「查看工具提示词」中可以查看、启用或关闭「邮件通知」，开关按对话保存，默认开启。未配置好邮箱时会显示缺失的配置；保存邮箱配置后同步更新工具状态和下一次发送使用的提示词。

AI 通过单个 JSON 代码块调用，无需提供邮箱或授权码：

```json
{"type":"send_email","subject":"任务完成通知","body":"任务已完成。\n请查看报告。"}
```

- `subject`：非空标题，最多 200 字符，不能换行。
- `body`：非空纯文本正文，最多 20000 字符，可以换行。
- 拒绝 `to`、`from`、SMTP、附件、HTML 及其他附加参数；收发邮箱固定读取本机已保存配置。
- 沿用现有平台的工具识别与回传链路，不依赖电脑操作开关；本地、SSH 和远程设备工作区均由运行客户端的本机发信。
- 只接纳当前活跃对话中、当前已确认用户消息之后产生的实时调用。历史消息、旧页面、旧任务以及暂停、全局急停或已关闭工具的调用不能发信。
- 每个调用在连接 SMTP 前持久化去重标记。重复页面事件、同一调用重复处理或进程在发送中重启，均不会自动重发。
- 主进程使用 QQ SMTP 465 端口、SSL/TLS 和证书验证发送纯文本邮件；授权码不进入 AI 的提示词或结果。
- 发送前重新核对任务与配置；切换对话、结束任务、暂停或修改配置会取消尚未完成的调用。邮件一旦提交，不能撤回；连接中断时可能只能给出不确定结果。
- 结果通过 `email_result` 回传当前 AI 对话，并在终端留一条结果提示。`sent` 表示 SMTP 服务器已接受；`failed` 表示发送未完成；`unknown` 表示无法确认是否已发送；`cancelled` 表示调用被取消。
- 回传时保留用户草稿，页面忙碌时仅重试回传结果，最多约两分钟；邮件本身不自动重发。不确定的回传也不会自动重复提交。

## 等待用户测试

智能体只构建，不运行测试或 Electron。用户可用 `npm run dev` 启动应用后检查：

1. 在未配置发件邮箱时，填写默认收件 QQ 邮箱并保存，确认显示「已配置」。
2. 关闭并重新打开设置、重新启动应用，确认默认收件地址保留；修改地址后再保存，确认新地址保留。
3. 输入其他域名邮箱或多个地址，确认保存失败，原来的默认收件地址保留。
4. 配置发件邮箱后，分别清除收件邮箱、清除发信配置，确认两者互不影响。

发信配置检查：

1. 首次进入邮件通知设置，填写邮箱和授权码，点击「保存配置」。
2. 关闭并重新打开设置，确认邮箱保留、授权码只显示已保存状态。
3. 点击「测试连接」，查看连接检查结果；此次操作不会发送邮件。
4. 使用错误授权码检查失败提示；更换邮箱但不填写授权码时应无法保存。
5. 清除发信配置后重新进入设置，确认发件邮箱和授权码状态均已清空。

AI 工具检查（会真实发送邮件，请由用户操作）：

1. 配置发件邮箱、SMTP 授权码和收件邮箱，在「查看工具提示词」确认「邮件通知」已开启。
2. 在对话中发送「请用邮件通知工具给我发送一封测试邮件，标题是 Web2Term 测试，正文是邮件通知工具已接入。」
3. 确认终端显示发送结果、AI 收到 `email_result` 并说明结果；检查收件箱和垃圾邮件箱，确认实际收到且未重复发送。
4. 在同一对话关闭邮件通知，确认工具提示词移除 `send_email` 定义；其他对话的开关不受影响。
5. 清除收件邮箱后再要求发信，确认提示补充配置；重新保存后无需重启应用即可再次调用。
6. 回到历史对话、刷新页面或重新打开应用，确认不会仅因扫描历史回复而发信。

纯离线测试使用伪存储、伪加密和伪 SMTP，不启动 Electron、不接触真实邮箱。可由用户运行，并将输出保存在临时目录：

```powershell
npm run test:qq-mail *> "$env:TEMP\web2term-qq-mail-tests.log"
```

覆盖收发配置、严格参数校验、持久化去重、配置缺失及损坏、SMTP 错误脱敏、不确定结果、发送取消、存储失败、页面识别、实时调用归属、电脑操作关闭时的工具桥接、端到端合成调用、结果回传重试和 SMTP 事务生命周期。所有 SMTP、页面、加密和存储均由合成依赖替代，不发真实邮件。测试结果由用户提供日志后再判断。

工具开关与提示词组合的离线回归另由用户运行：

```powershell
node --test tests/conversation-tools.test.mjs *> "$env:TEMP\web2term-conversation-tools-tests.log"
```
