# 专注对话中的会话压缩

在 DeepSeek 或 ChatGPT 的专注对话输入框中，于开头或新一行输入 `//`，选择“压缩会话”。支持继续输入“压缩”过滤、上下键、Enter 选择和 Esc 关闭；输入法选字的回车不会执行技能。只有已经产生会话地址、当前回答和工具处理结束后才能开始。

软件保留原会话 A，整理本地有效分支的文字、目录说明和必要执行结果，保存为 `source.md`。独立网页 B 复用当前平台登录状态，上传快照并生成 Markdown 交接摘要。软件读取完整回答、检查结构和本次结束标记，保存 `summary.md`。之后在同平台的独立新网页 C 上传摘要，收到完整读取确认后，在原工作区接入 C 的上下文。侧栏会话入口、名称、项目、终端连接与专注视图保持原样，不再新增“压缩后”会话。C 的第一轮只确认背景并等待用户输入。

B 和导入阶段的 C 没有终端、命令或工具执行回调，网页拦截器的执行、提示词注入和电脑操作识别均关闭。正常承接会话采用历史加载基线，不重放导入阶段的消息。继续复用原工作区和终端，工具开关来自开始压缩时的设置快照；旧任务的执行权限在承接时撤销。

专注视图通过本地历史链展示压缩前的有效消息、思考过程和执行卡片，后续回复接在下方。开始压缩时保存当前有效分支的不可变视图快照；之后在平台另行编辑 A 不会改变已承接的历史。滚动位置、过程展开状态、输入草稿和待发附件沿用原视图标识。旧历史可阅读和复制，旧消息不提供编辑、重新执行等会作用到当前网页的操作。旧执行输出延迟读取，只允许访问本条历史链中明确关联的记录。

系统生成的摘要导入消息（包括旧版“从上一会话导入的交接摘要（summary.md）：”）及导入确认回复不显示在本地会话摘要或专注视图中。隐藏依据本地压缩任务来源、消息标识及准确的任务协议，不按中文前缀模糊过滤用户消息。原始网页仍展示平台真实消息。

本地展示历史不重新发送给模型，也不计入压缩后的上下文估算。导入的摘要与确认回复继续保存在实际 C 会话记录中，并单独计入上下文统计；再次压缩时导出 C 的摘要和新消息，不重复导出仅用于回看的 A 历史。连续多次压缩沿用同一条本地展示历史链。旧版已创建的承接工作区会从持久化压缩记录恢复展示来源并隐藏导入消息，保留现有入口，不自动合并或删除历史工作区。

正常压缩在后台运行。专注对话保留原来的消息和滚动区域，在输入框上方显示一行加载动画、“正在压缩对话…”和“取消”，不展示导出、上传、模型回答或摘要导入页面。完成后在原视图继续聊天。失败或暂停时，这一行提供“重试”和“处理问题”；只有用户点击“处理问题”才打开原生处理页，供登录、验证或补全回答。点击“处理完成，继续压缩”后收起页面，在后台继续。

切换会话或平台时暂停后续提交；返回来源会话后继续，不要求展示压缩网页。若上传中途被打断，可从“重试”恢复。全局急停会中止本次等待，解除急停后也需显式重试。取消会释放网页和本次等待；已发出的平台消息和已保存文件保留。

点击“取消压缩”后，进度卡一并收起，恢复完整对话区域和输入；切换会话或重启后不会重新显示已取消的卡片。取消状态仍保存在本地，导出文件继续保留，也可以重新输入 `//` 发起新的压缩。

文件保存在软件用户数据目录 `exports/compactions/<任务编号>/source.md` 和 `summary.md`，异常处理页保留定位文件入口。阶段、来源、文件哈希、压缩与承接网页地址、两次发送状态及承接会话编号保存在本地设置中。提交前先保存“不确定”边界；确认消息后记录成功。重启不会自动发送，用户重试后从已有阶段恢复；不确定发送只检查原网页，不重新提交。若提交结果不明且未能保存会话地址，需先核对平台历史；软件不会猜测另建一份。

本地快照不保证覆盖网页尚未捕获的早期历史。原图片和文档只记录已知附件信息及历史文字结论，不携带原件。执行记录中超过 12,000 字符的单条日志保留前 4,000 和后 8,000 字符，明确标记省略，完整输出仍在原会话本地记录中。整份快照超过 80,000 估算 token 或 300,000 字符时，首版停止并说明原因，不静默删除对话。预算是应用的保守上限，不代表平台真实上下文或附件额度。

摘要保留八部分：当前目标、用户约束、已确认事实、已完成事项与验证、关键决定与失败尝试、文件与执行环境、未完成事项与下一步、缺失信息与未验证事项。结束标记、平台空闲和正文稳定只用于判断传输完整性，不保证语义没有遗漏。

压缩成功后，在旧历史与后续新消息之间显示一条居中的“✓ 会话已压缩”分隔提示。提示由本地承接链生成，每次成功承接一条，重启后仍保留；失败、取消不产生提示。它不是用户或模型消息，不参与 Token 估算，也不导出到下一轮摘要。旧版已承接的历史链同样补出提示。

## 长度预算与提示词调整（2026-11-02）

本地记录确认过一例内容膨胀：`source.md` 约 3,438 估算 token，`summary.md` 却有 5,251，确认回复约 206，加导入提示后共 5,815。旧提示词固定要求“3,000～5,000 token”，没有相对预算，也没有成功前的收益检查。这里是实际摘要变长，不是把仅供展示的旧历史再次计数。

新任务以开始前专注视图使用的同一套上下文估算为基准，冻结到任务预算中；不使用带日志、标题等内容的导出文件大小冒充当前上下文。摘要上限为原上下文的 50% 且不超过 3,000 估算 token；目标为上限的 80% 且不超过 2,000。还需为导入提示和确认回复预留空间，摘要加导入开销总计不得超过原上下文的 70%。这些比例是本软件的初始工程策略，不是平台公布的标准。低于 1,000 估算 token 或无法抵消导入开销的会话会保留原样，不发起网页请求。

摘要生成后先检查长度，超限则停在 B，不上传到 C，不截断内容。可通过“处理问题 → 复制补全提示词”让同一个 B 页精简，完成后重试，不重复上传原快照。保存过的旧摘要若超出新预算，提示取消后重新压缩。收到 C 确认后还会检查实际摘要、导入提示及回复的总量；不满足预算就不接入原工作区，明确保留原会话。后续正常聊天及新的完整提示词注入会增加上下文，不属于本次压缩收益承诺。

提示词改为“上下文检查点”：记录最新目标与停点、有效用户约束、关键事实、实际结果、影响后续的决定，以及真正未完成的下一步。合并旧摘要中仍有效的信息，不累积嵌套摘要；最新更正覆盖旧说法；任务完成时明确等待用户新消息，避免压缩后重复执行已完成任务。命令和日志优先保留结论、必要路径、精确错误及标识，不抄整份脚本，不扩写背景。新会话只作一句读取确认，不再复述摘要。

参考官方公开资料：

- [OpenAI Agents SDK 会话记忆示例](https://developers.openai.com/cookbook/examples/agents_sdk/session_memory)提供了明确的摘要提示词：先核对矛盾、时间顺序及未知事实，再输出简洁的环境、结果、标识、状态与下一步。示例还把较新的完整轮次与较早摘要分开保留。此处借鉴状态交接与事实校验的原则，保留本软件既有的八节输出协议。
- [Anthropic 上下文工程说明](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)说明 Claude Code 保留关键决定、未解决问题和实现细节，清理冗余工具输出；同时指出过度压缩可能丢失关键上下文。因此此处超限会停止交接，让模型重新组织信息，而不是机械截断。
- [OpenAI Compaction 官方文档](https://developers.openai.com/api/docs/guides/compaction)说明 API 原生压缩返回不可读的压缩状态项。网页附件摘要不能等同于该机制；当前实现继续兼容 DeepSeek/ChatGPT 网页，不改用 API，也不声称获取了网页端私有提示词。

文件读取完整性指本次上传的 `source.md` / `summary.md` 正文是否从头到尾读完。快照未包含早期历史、原附件未迁移、日志有明确节选、项目状态待验证，都属于需要保留的背景缺口，不能因此判定本次文件读取失败。协议只认回复最后一行的结束状态，正文中引用旧失败标记不改变本次成功状态。

旧任务若已完整读完 `source.md`，却因为历史材料有缺口而输出失败标记：点击“处理问题”，再点“复制补全提示词”，粘贴到同一个压缩网页的输入框并发送。等它重新完整输出摘要后，再点“处理完成，继续压缩”。这会沿用已上传的快照和原压缩会话，不自动重复提交、不修改原始文件，也不直接忽略失败标记。

后台页在首次导航前，先在空白视图上初始化非零内容尺寸，然后隐藏；隐藏、加载和导航后重新设置 `backgroundThrottling=false`。收起处理页时保留最后一次有效尺寸，不设置为零，不重新显示已加载页面来保活。任务根据来源会话及全局急停判断能否推进，原生页面的展示状态仅控制异常处理 UI。该顺序沿用项目既有隐藏渲染修复；[Electron 官方说明](https://www.electronjs.org/docs/latest/api/web-contents#contentssetbackgroundthrottlingallowed)指出后台节流设置也影响页面可见性 API。离线模型不能证明第三方网页在隐藏状态下一定正常挂载消息，需用户真实复测。

诊断日志位于 `%TEMP%/gpt-login-diag/conversation-compaction-*.log`，仅记录阶段、平台、任务编号、发送状态及计数，不记录对话或摘要正文。现有附件日志仍使用同目录的平台文件发送日志。

离线回归由用户运行（不启动 Electron、不联网）：

```powershell
node --test tests/conversation-compaction.test.mjs tests/compaction-page.test.mjs tests/conversation-continuity.test.mjs tests/long-task-performance.test.mjs tests/focus-smart-ui.test.mjs tests/focus-token-usage.test.mjs
```

真实验收由用户使用 `npm run dev` 运行：

1. 分别在 DeepSeek、ChatGPT 已有会话中输入 `//`，检查鼠标、键盘、中文输入法、普通 URL 和输入草稿保留。
2. 分别在 DeepSeek、ChatGPT 不打开“处理问题”、不切换原始视图，完整走一遍 A → B → C；过程中只显示输入框上方的一行状态。完成后仍在同一个侧栏入口、名称与专注视图，原历史和执行卡片仍可回看，滚动位置与草稿保留；不显示摘要导入和确认消息。发送新问题，回复接在原历史下方。
3. 查看两份文件，确认编辑分支、用户禁止事项、执行结果、未验证事项和待办保留，图片或文档缺失明确标记。检查新会话项目与终端绑定。
4. 在上传、压缩生成、摘要导入阶段分别断网、取消、切换会话和重启；从状态行重试，检查没有重复发送。取消后状态行消失。发送结果不确定时，点击“处理问题”核对原网页。
5. 让平台中途截断或拒绝附件，检查未生成摘要时不会进入 C，承接未确认时不会创建完成状态；页面未就绪时应提供处理入口。检查手动展开/收起、登录、完成验证或补全后能继续，处理页不会覆盖其他会话或设置界面。
6. 继续聊天并再次压缩，确认历史不重复，新的 `source.md` 包含已导入摘要和之后的新消息，不重复携带仅供回看的旧历史。重启软件，确认原入口、标题、历史和隐藏规则恢复。检查上下文估算只包含当前模型上下文。

交付状态为“构建通过，等待测试”。构建不代表真实网页上传、回答读取或摘要质量已验证。
